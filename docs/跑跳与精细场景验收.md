# 《江城有灯》跑跳与精细场景验收

本轮检验角色跑动、跳跃和近距离街景是否形成一致体验。验收分为物理行为、真实输入、画面与性能四部分；各部分独立记录，不能由单元测试替代实机画面结论。

**当前状态（2026-09-09）：本轮最终专项与性能构建为 `index-BVPvVAs2.js`，纯测试 81/81、真实输入与双巷路线 51/51 通过，64.96 秒游玩视频已完成抽样审查，300 秒本机白天移动性能达到门槛（平均 119.83 FPS、最慢 1% 对应 89.31 FPS）。完整主线证据属于前一版 `index-BArURk08.js`：第三人称 18/18、第一人称 19/19，均无浏览器异常及失败资产请求。** 两版仅有 `src/exploration.js` 与 `src/world.js` 的 held 控制两处差异，以及 `src/main.js` 新增的只读物理时钟字段，仍按构建分别记录；不声称 BVP 已重新完整通关。第 7、9 节保留早期 kw 近墙约129°/64ms突转及后续失败，不能由目录名称推断最终通过。

## 1. 操作与物理门槛

| 项目 | 验收要求 | 验证方式 |
| --- | --- | --- |
| 起跳响应 | 有效按下空格后，下一次物理帧离地；60 Hz 首帧上升至少 8 cm | 单元测试＋真实键盘录像 |
| 普通跳高度与时长 | 平地最高离地 0.90–1.10 m，滞空 0.55–0.67 s；落地精确回到当前地面，没有残留垂直速度 | 30/60/120 Hz 采样 |
| 帧率稳定 | 三种步长的最高点差 <1.5 cm、落地时间差 <35 ms | 同一初始条件直接调用实际物理模块 |
| 输入次数 | 一次按下只产生一次跳跃；持续按住及浏览器 repeat 事件不能连续跳；释放再按可再次跳 | 单元测试＋真实 `keyboard.down` 重复事件 |
| 落地缓冲 | 落地前约 80 ms 再按空格，落地后只接一次跳；过早的空中按键应过期 | 单元测试 |
| 离边宽限 | 离开支撑面 50 ms 内可以起跳，130 ms 后不能在空中起跳 | 物理边界测试；不意味着解锁跳上屋顶 |
| 低顶棚 | 5 mm 薄棚也不能向上穿透；恰好站立净空不能被过滤；顶棚限制不把角色压入地面 | 100 ms 较大帧间隔的扫掠回归 |
| 横向头碰 | 头部高度与雨棚重叠时，不能从侧面钻入或跨过薄边；已擦入安全余量时允许退出，不能继续深入 | 实际 `canPlayerStep` 与顶棚扫掠 |
| 路线约束 | 空中同样遵守墙、危险区、江岸、地图边界与小院台阶入口规则；低墙不因离地自动变成可越障路线 | 既有通行判断与跑跳集成测试 |
| 导航一致性 | 站立时规划出的每段路线，必须能由同一角色的实际通行判断接受；低檐绕行、有净空的雨棚可直行；仅遮镜头的树冠不能成为实体棚 | 低净空路线回归＋`solid:false` 树冠回归＋实机社区路线 |
| 重置 | 新故事或重新定位后，脚底在新地面、垂直速度及缓冲为零，没有旧跳跃继续播放 | 实际 `setPosition`＋直接 reset |

运行参数为初速 6.6 m/s、重力 22 m/s²、缓冲 120 ms、宽限 100 ms。物理内部最大子步 1/120 s。参数服务于短促、清楚的街区探索动作；不能把数值本身等同于好手感。

## 2. 菜单、对话和视角

| 场景 | 必须发生的行为 |
| --- | --- |
| 空中打开地图、设置或普通面板 | 阻止新的跳跃和水平移动，当前垂直运动继续安全落地；关闭面板不重放旧按键 |
| 回主画面 | 冻结当前身体高度、速度和物理计时；继续故事后只推进正常一帧，不把停留时间累计成坠落；未消费的起跳指令清除 |
| 记忆/影片暂停 | 物理与缓冲计时按暂停语义处理；若同时处于 blocked，先取消旧起跳缓冲，恢复后不能幽灵跳 |
| 空中按 E | 先记录交谈请求，落地后在同一地点开始 3D 对话；没有半空定格、落地后又恢复半空的情况 |
| 对话最后一句按空格 | 该次事件只完成剧情翻页/关闭，不传播成探索中的起跳；再独立按空格才跳 |
| UI 控件焦点 | 输入框、选择框、按钮等消费空格时不能触发跳跃；进入和退出界面后探索焦点可正常恢复 |
| 空中切换第一/第三人称 | 身体位置、垂直速度与剩余飞行过程保持；第一人称眼高随身体在同一帧更新 |

单元测试包含强制在空中进入对话的兜底检查，确保保存的是地面位置。实机仍需通过真正的 E 键验证正常排队流程；不能以兜底 reset 代替该流程通过。

## 3. 动作与镜头的画面门槛

- 行走与跑步有可辨识的步幅、摆臂和身体重心变化；起步、停止和转向不能像滑动物件。站立脚、衣服、包与头发的运动需要逐段看录像，不以关节参数存在为通过。
- 起跳、空中收腿、落地预备与落地缓冲连续可读。空中不继续播放贴地踏步，落地后不把脚长时间埋入地面，不出现膝盖反折或瞬间换肢。
- 默认第三人称保持已定的近景比例：静立角色约占画面高度 32%–40%。普通跳全过程应看见头部和脚部；不能为保全角色而把镜头升至屋顶。墙角场景的侧移辅助应稳定，不能左右反复抢镜头。
- 第一人称无镜头滚转，观察方向不因起跳自动改变。眼高跟随身体；停在主画面期间画面与物理状态不能互相矛盾。
- 3D 对话时，实际角色网格上缘避开顶部标题，下缘至少离字幕 20 px；机位计算保留 22 px 余量。不能只用根节点或近似脚点证明鞋子没有被遮住。
- 跳跃碰雨棚、近墙跑动、低角度观察都应检查镜头穿墙、屋檐遮满屏幕和角色突然消失。参数采样通过后还需人工观看连续录像。

验收至少覆盖 1440×900 与 1920×1080 横屏。桌面窄视口只能说明响应式布局，不能写成手机真机通过。

## 4. 精细街景与武汉识别度

以玩家日常可到达的 2–5 m 观察距离验收，不能仅靠远景缩略图或高空俯瞰评价精细度。

| 观察对象 | 画面要求 |
| --- | --- |
| 修理铺、早餐铺、小院、码头、社区 | 功能和轮廓可辨，门窗有进深，檐口、台阶、招牌、管线与材料边缘有可信层次。近景不依赖单张正立面图片支撑全部体积 |
| 主楼与背景楼 | 同一套比例与材质语言贯穿街区；背景楼允许减少细节，但不能回到无门窗进深的占位盒子或与前景冲突的写实照片 |
| 地面和小物件 | 潮湿铺地、墙脚、门槛和桌面接触清楚；灯、收音机、早餐器具、竹椅等经得起任务镜头观察，不悬空、不明显穿插 |
| 武汉线索 | 江汉关/长江大桥等远景轮廓、轮渡与江面、汉口老街生活细节和过早饮食形成组合识别；不是靠一个“武汉”文字标签证明地域性 |
| 城市空间与历史 | 晴川里与人物为原创虚构；地标在视线中的艺术安排和真实地理关系应区分，涉及年代、历史事件和应急信息的文本另行核实 |
| 光照与天气 | 晴天、雨中、雨后保持相同空间关系；暖窗灯和雨水反光服务于人物故事，不造成高光闪烁、黑洞门窗或不可读的行走区域 |

每个主地点至少保留一张接近玩家眼高的代表画面、一张任务交互画面。需要检查门窗侧面和转角，避免只对正面贴图评分。与参考的精细度、动作可读性分别比较，不将整体风格相近写成建模质量已完全达到。

街区地图与真实场景共享 `STREET_COMPOSITION_MAP`：共 11 个新增构件，其中 5 个可通行区域。工具棚表现为有屋顶建筑，墙和护栏表现为窄条构筑物；工具巷、过早侧巷、路口空地和缓坡使用铺地，缓坡以方向线及“缓坡”标识，不能误画成房屋。大小地图保留原有坐标、路线叠加和比例，逐项检查矩形边界与 SVG 变换。冻结构建的实际 UI 图在 [地图证据目录](../output/qa/maps/new-passages/release-kw-JDH9m/report.json)；地图可读性通过不代替角色实走两条巷道。

## 5. 实机执行与证据规则

1. 主任务明确冻结可测构建后才启动浏览器；候选构建用于发现问题，最终验收必须重新关联最终构建。
2. 使用一个全新浏览器 context，一段连续录像。通过真实鼠标、键盘和可见地图操作完成流程，不注入存档、角色位置或剧情状态。
3. 可以读取 `window.__JIANGCHENG__` 的只读诊断来记录位置、地面高度、运动状态、头脚投影、镜头旋转、modal 和路线。禁止调用应用方法改变状态来制造通过。
4. 启动时强制校验实际加载的 JS 构建文件名；报告保留构建 URL、浏览器/渲染器、视口、DPR、运行阶段、所有截图、逐次采样与异常。
5. 单步失败仍保留原始报告、截图和录像。修复后使用新的运行目录，不能覆盖失败并将历史改写为通过。
6. 独立记录“自动断言通过”“人工观看通过”和“尚未覆盖”。调试 smoke、旧构建数据、不同机器的 FPS 不能混合成最终结论。

纯测试命令：

```bash
node --test tests/traversal.test.js
npm test
```

浏览器脚本为 `tests/traversal-browser.mjs`。必须先取得主任务确认的实际构建文件名，再使用 `EXPECTED_BUILD_ASSET` 指定它；默认地址 `http://localhost:4173/`，可用 `QA_OUTPUT_DIR` 指定新的独立证据目录。示例中的哈希须替换为确认后的实际值：

```bash
QA_STAGE=final QA_WIDTH=1920 QA_HEIGHT=1080 EXPECTED_BUILD_ASSET=/assets/index-实际哈希.js GAME_URL=http://127.0.0.1:4173/ QA_OUTPUT_DIR=output/qa/traversal/final/input node tests/traversal-browser.mjs
```

`QA_WIDTH` / `QA_HEIGHT` 同时设置实际浏览器和录制尺寸，默认仍为 1440×900；鼠标观察锚点随视口中心调整。`QA_TOUR=1` 可以在明确标为候选的阶段追加路线，不必把候选误标为 final。

U8 候选已跑完功能专项与 60–90 秒连续游玩路线，覆盖修理铺、小院、早餐铺、码头，以及真实跑跳和 3D 对话。功能录屏和游玩片段分别列证据，不能将 32 秒的功能脚本等同于充分的街景体验记录。

## 6. 性能标准

桌面目标为同机 1920×1080、DPR 1、精致画质，加载稳定后持续正常跑动与探索平均至少 60 FPS。记录 P99 帧间隔、最慢 1% 帧和测试时长；重复出现超过 100 ms 的停顿需给出原因并整改。最终还应做至少五分钟含转角、主要地点与天气变化的持续观察。

性能测试应与输入录像分开执行，使用同一冻结构建、同一设备和单浏览器，避免录制开销或并发浏览器影响结论。BVP 的 300 秒本机白天结果见第 10.6 节；旧构建的高帧率不自动沿用，天气与设备覆盖边界单列。
