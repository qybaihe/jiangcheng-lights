## 声音设计与接入顺序

探索段使街区有轻松走动的节奏，不用灾难预告式低音或紧迫鼓点。回忆段减少打击与密度，把听觉空间留给人物的日常动作和对白。尾声延续亲密钢琴，再展开弦乐质感；克制、有一点回望的情绪，不做凯旋大合唱。

三条音乐使用固定生成文件，在运行时重复使用，不随每句台词重新生成或切换音色。配乐不强塞“武汉主题音阶”或旅游宣传锣鼓；武汉识别来自街区、物件、语言和生活声音共同建立。

建议播放器按以下顺序选曲：

1. `ending` 场景优先使用尾声曲，包括终章的两张童年 CG 与回到 3D 后的外公语音。
2. 其他明确标记为过去的段落使用回忆曲。
3. 现在时对话、现实街区探索使用探索曲。

只在 cue 改变时做约 1.5–2 秒交叉淡入，不在每句对话或每张 CG 上重启。台词播放时将当前音乐再压低约 8–10 dB，短时间淡出、较慢恢复；避免一句话之间忽大忽小。实际音量应由集成版的人声与手机扬声器试听调整，不能仅凭 LUFS 数字推断最终混音。

雨声走独立环境声通道，根据场景天气出现，不替代音乐。翻页只在实际翻页或展开照片时响一次；旋钮短音适合明确的一次调节或完成动作，避免长按时无限叠加。脚步继续使用既有 `src/foley.js`，本轮没有重复生成。

## 已核实的生成接口

沿用 `tools/media.py` 与本机 `paid_ads_inspiration/app/model_gateway/text_to_audio.py` 已有的服务契约：同步 POST 请求体仅有 `{"prompt": "..."}`，响应为 `base_resp`、`audio_base64` 与可选 `output_format`，解码后得到 WAV。

该接口没有独立时长、乐器 ID、随机种子、参考音乐或音色锁定字段。72 秒及编制要求写在 prompt 中，之后对实际文件测量。三条入选音乐源文件均实测 **72.000 秒、40 kHz、双声道 PCM WAV**，不是把十秒素材重复接成一分钟。

底层模型名称与版本未由接口暴露，因此来源写为 `text_to_audio`，不称作已证实的 Seed Audio、Seedance、MusicGen 或某一特定音乐模型。接口使用既有项目契约；生成工具不打印 `.env`、认证字段或请求敏感信息。辅助聆听工具仅通过本地既有多模态网关读取已生成声音，认证信息不进入公共 manifest。

提示词能约束方向，不能保证每种乐器都严格实现。实际试听听到探索段以吉他为主、回忆段是钢琴与铺底；尾声第二版形成了钢琴与渐入弦乐质感，弦乐是否真实录制的乐团无法由生成服务确认。本文与 manifest 记录实际听感，不把提示词中的编制当作验收事实。

## 剪辑与循环方式

三条音乐均保留独立完整生成源。探索段末尾约 2 秒出现明显收束，所以剪去末尾 3 秒，再做 1.5 秒首尾重叠，得到 67.5 秒；回忆和尾声仅做 1.5 秒首尾重叠，得到 70.5 秒。

循环处理将首尾 1.5 秒重叠为一个平滑衔接片段，其余内容按原顺序仅播放一次。没有复制短片段以凑长度，也没有改变速度。雨声使用同样首尾处理，从 12 秒得到 10.5 秒的环境循环；它不是一分钟配乐，因此不按 BGM 时长统计。

翻页从生成的 4 秒录音中取 1.35–2.55 秒，保留主要纸张摩擦，减少触发后等待。旋钮从入选的 3 秒录音中取 0.2–0.9 秒，保留第一组机械卡嗒。两项动作音效边缘加毫秒级淡入淡出，再统一响度；没有补入合成波形。

## 质检与版本选择

所有六个入选源音频均做了全段模型辅助聆听，检查是否有说话、歌声、呼吸等人声、动作是否匹配、是否有突发失真或明显短循环。辅助聆听通过带完整音频的中性 MP4 载体完成，报告在 `output/story-audio/qa/`。这不是人工试听，manifest 明确写 `humanListened: false`、`modelAssistedListening: true`。

三条音乐与雨声另各检查了“成品最后七秒 → 成品前七秒”的十四秒接缝片段，并结合样本边界数值检查。报告均未发现分散注意力的接缝爆音或停顿；模型对音乐短句重复的描述只作为观察，不当作逐样本证据。完整源段报告未检出明显的十秒短片机械循环。

最终主文件全部实测 **零削波样本**，三条音乐没有低于 −55 dB 持续 0.4 秒以上的静音断口。循环边界样本跳变量分别为探索 −45.42 dBFS、回忆 −53.67 dBFS、尾声 −45.73 dBFS、雨声 −36.60 dBFS。雨声是连续随机声纹，边界指标结合接缝试听判断，不与音乐波形直接作优劣比较。

版本记录：

- 探索 `v1`、回忆 `v1` 入选。
- 尾声 `v1` 完成但偏吉他，与探索接近；重新收紧钢琴/弦乐提示后，选择 `v2`。
- 雨声首次 24 秒请求返回 HTTP 504，没有有效音频文件。缩短为 12 秒后 `v2` 成功并入选。
- 翻页 `v1` 入选。
- 旋钮 `v1` 被辅助聆听判为类似吸鼻/呼气，与动作不符，未发布。`v2` 清楚呈现机械开关声后入选，并剪出第一组动作。

发布工具会拒绝不足 60 秒的 BGM，也会拒绝存在人声证据或未通过器乐判定的音乐。源 WAV、完整 prompt、请求 hash、源文件 hash、生成时间与实际时长保存在 `output/story-audio/sources/`；公共 manifest 记录可用文件及来源和测量信息，只发布入选版本。

## 复现与文件契约

专用工具不修改主剧情或播放器：

```sh
# 只有 generate / build 会请求生成；命中同一版本缓存不会再付出一次调用。
python3 tools/story_music.py generate explore
.venv/bin/python tools/story_music_qa.py explore
python3 tools/story_music.py publish explore
.venv/bin/python tools/story_music_qa.py explore --loop-seam
python3 tools/story_music.py attach-seam-qa explore

# 尾声、小雨、旋钮入选的是 v2；发布时使用相应版本。
python3 tools/story_music.py publish ending --version v2

# 离线重新编码 MP3 兼容文件并核对最终时长、hash 与削波。
python3 tools/story_music.py finalize
```

修改 prompt 后需要使用新的 `--version`，不能覆盖同名旧请求。当前工具里的尾声、雨声、旋钮 prompt 已是 `v2` 版本；各历史 prompt 都留在源文件旁。

播放器所需的稳定结构为：

```json
{
  "version": 1,
  "tracks": {
    "explore": {"url": "/media/audio/bgm-explore.ogg", "duration": 67.5, "loop": true},
    "memory": {"url": "/media/audio/bgm-memory.ogg", "duration": 70.5, "loop": true},
    "ending": {"url": "/media/audio/bgm-ending.ogg", "duration": 70.5, "loop": true}
  },
  "sfx": {
    "page": {"url": "/media/audio/sfx-page.ogg", "duration": 1.2, "loop": false},
    "radio": {"url": "/media/audio/sfx-radio.ogg", "duration": 0.7, "loop": false},
    "rain": {"url": "/media/audio/sfx-rain.ogg", "duration": 10.5, "loop": true}
  }
}
```

实际 manifest 还含 `fallbackUrl`、`source`、`loudness`、文件 hash、大小与 `qa`，以上仅省略展示。最终曲目选择、跨场景交叉淡入、TTS 压低 BGM、页面失焦与总音量开关仍由播放器整合任务验证；本次素材检查不替代完整游戏里的听感验收。
