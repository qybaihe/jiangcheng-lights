# 首次载具中央指引 v1

## 体验

第一次走近自行车或汽车，用一张屏幕中央的奶油纸教学卡解释“这件场景道具真的能用”。左侧为与场景配色匹配的车辆插画；右侧大号 F 键提示、两行驾驶按键和一个确认按钮。背景仍留着 3D 街景，不进入剧情或发放奖励。

- 自行车未借用：F「借车并骑上」。
- 自行车已借用：F「骑上自行车」，避免给旧存档显示假的重新解锁。
- 汽车：F「上车驾驶」，轿车/小货车共用一次教学记录，但插画展示实际车型与车漆。
- W / S 前进后退，A / D 左右转向，空格按铃或鸣笛，F 停车下车。
- 主按钮、右上角 ×、Enter、空格、Esc 均确认提示；F 本身只被拦截，确认不等于上车。
- 自行车、汽车各自确认一次后随当前存档保存。旧存档未有确认字段时给一次文案准确的提醒。

## 独立模块

`src/vehicle-guide-progress.js`

- `normalizeVehicleGuideProgress(value)` → `{version:1, seen:[]}`，只保留 `bicycle`、`car`。
- `acknowledgeVehicleGuide(value, kind)` → 幂等的新进度对象。
- `vehicleGuideKind(prop)` → 用真实道具 ID 映射，非仅信任 `propType`。
- `firstVehicleGuideCandidate({state, nearby, mode, active, blocked, modal, arrival, grounded, pending, hidden})` → 候选或 null。
- `createVehicleGuideGate()` → `consider(context)`、`presented(candidate)`、`reset()`、`diagnostics()`。

Gate 只保留当前道具的临时出现状态，防止被其他界面抢占时立刻反复弹出。离开该道具范围后重新允许；永久的“已提醒”只由存档决定。

`src/ui/first-vehicle-guide.js`

- `firstVehicleGuideCopy(candidate)` / `firstVehicleGuideMarkup(candidate)`。
- `mountFirstVehicleGuide(root, {candidate, onAcknowledge(kind,{reason,id}), autoFocus:true})`。
- 返回 `acknowledge(reason)` / `diagnostics()` / `dispose()`。
- `dispose` 只清理，不伪造已读、不操作场景。

## 主程序接入契约

```js
// 已由主程序统一处理，不在组件内部各自碰 world / save。
state.vehicleGuides = normalizeVehicleGuideProgress(state.vehicleGuides);
const gate = createVehicleGuideGate();
const candidate = gate.consider({
  state, nearby:world.getNearbyProp(), mode:world.getPropState().mode,
  active:world.active, blocked:world.blocked, modal,
  arrival:world.getArrivalView()?.active,
  grounded:world.playerMotion?.grounded,
  pending:pendingSceneInteraction || pendingInteraction,
  hidden:document.hidden,
});
```

候选有效后，使用原 `openModal` 协议，以 `vehicle-guide` 类型、`first-vehicle-overlay` CSS 类和 `first-vehicle-guide-root` 容器挂载。`onAcknowledge` 仅更新 `state.vehicleGuides`、保存、关闭卡片。

主动 F / 场景点击使用入口也需先确认教学，避免玩家在界面轮询前快速上车；展示后立即 return，不继续执行原使用。所有 CG、对白、地图、菜单、入城镜头、在空中和自动接近都暂缓自动显示。

组件会在根元素捕获 keydown，阻止同一个 Enter / 空格事件穿透；**主程序仍应负责**统一清空 `world.keys`、输入缓冲和自动接近，并在已按下的按键释放以前屏蔽原操作。记录按键状态的监听应在 window / document 捕获阶段，不能只依赖冒泡。
