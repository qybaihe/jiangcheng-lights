## 2. 三段画面为什么能让人想走进去

**约 0—10 秒：街道移动。** 主角在画面中有足够体积，背包、鞋和手臂动作能一眼认出。道路不是从一端看穿的平面：转角、路面起伏、路边树木和建筑遮挡持续改变前后景。跑几步就能看到新的门面与远景，移动本身就有回报。

**约 10—18 秒：进入广场、靠近人物。** 狭窄街道释放成一个小节点，售货机、邮箱、店招、桌子和居民围成生活场景。人物的对白出现在身边，玩家仍然看得到自己的角色、对方和离开的路。地点名称是短暂的场景提示，解说的大字幕属于视频包装，不是应该复制的游戏 HUD。

**约 18—27 秒：穿过侧巷。** 狭巷、架空构件、侧门、箱子和电话亭改变空间节奏。贴近时建筑有侧面和进深，角色与街道处于同一个可信尺度。观看者会预期转角后还有东西，而不是把每栋楼当成背景板。

画面有明显的地平线倾斜与建筑透视变化，原作介绍也明确提到小星球；仅凭这些仍不确定其所有几何和镜头实现。可以学习它的空间变化；武汉 PC 版应保持稳定地平线，避免把倾斜和摇摆当作必须复制的效果。

## 3. 真正需要统一的五件事

| 维度 | 参考中可见的表现 | 武汉版本的制作要求 |
| --- | --- | --- |
| 材质与边缘 | 大块色面、有限明暗、深色轮廓、少量建筑细线 | 建筑、人物、植物、道具共用卡通美术规则；减少照片纹理的噪声和写实高光 |
| 镜头 | 近距离第三人称，前进方向有足够空间 | 默认采用贴近阿遥的探索镜头；第一人称保留；俯瞰视角用于看整体 |
| 动作 | 可辨认的迈步、摆臂、转身与站立姿态 | 加减速、转向和走跑过渡；脚底接地；提物与递物有动作 |
| 街区 | 窄巷、转角、开阔节点、上下层构件交替 | 用里分院门、天井、骑楼或连廊、望江巷口组织可走路线；每个转角有构图目的 |
| 交互 | 人物与对白留在场景内，常驻界面较少 | 轻量靠近提示、场景内普通对话、明确的物品交接；仅旧时记忆进入演出 |

“卡通”不等于低精度。参考的克制来自把细节放在轮廓、转折、角色和生活物件上，而不是给所有表面平均增加纹理。

## 5. PC 横屏的具体规格

### 镜头与操控

- 以 1920 × 1080 为主验收尺寸，同时检查 1440 × 900 与 2560 × 1440。宽屏增加横向环境信息，不能拉伸人物或 UI。
- 普通探索时，主角高度先控制在画面高度的 **32%—40%**；脚部位于画面下方但留出地面判断空间。数值须用实际角色比例与场景微调。
- 镜头距离先从 **3.8—4.8 米**、FOV **50°—58°**试起。镜头目标靠近上身，避免过分俯视头顶。
- WASD 相对镜头移动，Shift 跑步；鼠标观察。停止时允许看店招、窗户和远处地标；移动后的自动回正应缓和，不能夺走正在手动观察的镜头。
- 默认不加镜头滚转、持续上下晃动或强制跑步变焦。玩家转角时看清路比制造晃动更重要。
- 遇墙收短观察距离，不穿墙、不突然升到屋顶。出遮挡后平稳回到原距离。
- 对话结束恢复进入前的观察方向和视角模式，不能把第一人称玩家强行送回第三人称。

### 屏幕布局

- 常驻目标位于左上安全区，最多显示一条当前任务；保留明确的下一步方向。
- 小地图位于右上，展开后查看全图；普通探索不让大型信息框覆盖街道中心。
- 靠近人物或物件时，提示放在对象附近，并做遮挡、距离和屏幕边界处理。
- 普通对白继续呈现在 3D 中。角色面部、手部与路口不被对话条遮挡；保留退出和继续功能。
- 现有检修台、相册、应急包、现场判断的精修界面延续使用；打开和关闭都保持正在交互的场景位置与任务关系。

### 美术与角色

- 大色块建议为暖米白墙面、青灰屋瓦、偏青天空、克制的草绿与砖红；金黄色只用于灯、早餐和少量交互焦点。
- 建筑与主要道具使用受控明暗，先试两至三档，再观察脸部与圆柱物体是否生硬。该数值是本项目方案，不是对原片着色器的断言。
- 轮廓线在 1080p 下先试约 1—1.5 像素；远处减弱或取消。建筑内部线来自窗框、材料分界与手绘结构线，不把三角网格全部描出来。
- 主角先完成一个有完整骨骼、清楚轮廓、可近看的阿遥。至少具备待机、走、跑、起停、左右转向、交谈、持物、递物。
- 用步行距离匹配步频，检查脚滑；衣服与背包有轻微次级动作，幅度服从温情、日常的基调。
- 街坊动作结合职业：蔡姨拌面与整理食盒、婆婆收衣或照料盆栽、修理台前俯身整理零件。多人并排站立摇摆不能代替生活感。

## 6. 将它变成武汉，而不是换招牌

制作一条“**修理铺门口 → 里分院门 → 天井与早餐铺 → 望江巷口**”的连续精品路线。

开场从近处的陆记木门、修理台与白铁壶建立生活尺度；转进院门，看到晾衣、楼梯、盆栽和二楼住户；早餐节点让热干面、豆皮、食盒与店主动作发生联系；走到巷口再用江面、轮渡和经核对的江汉关轮廓建立城市辨识。

汉口的主街不应为模仿原片而变成连续大山坡。空间高低变化可以来自台阶、院落、过街构件和视线遮露。主要老年居民行动路线应有合理、可通行的选择。

不要把所有地标同时挤在同一条真实街道旁。晴川里仍为虚构拼合街区，建筑、距离和年代信息需要说明与核对。武汉辨识来自建筑生活形态、江岸关系与具体物件共同出现。

## 7. 制作顺序与验收门槛

### A. 先完成一段可操作样板

先做约 60—90 秒可连续行走的精品路线，包含一个转角、一个窄巷、一个开阔节点、两位有生活动作的街坊、一次原地交谈与一件可交接的旧物。玩家可以停下、回头、贴近墙面；不能只依靠固定镜头的视频展示效果。

这一轮同时解决近身相机、移动过渡、主角动作、卡通材质与遮挡。五项一起成立后再扩到整条街，避免镜头拉近以后只能看见粗糙模型。

### B. 替换可进入的近景空间与核心角色

先完善玩家会靠近的门、窗、柜台、侧巷和室内节点。采用统一的原画/建模规则、模块化建筑、适当 LOD、合并纹理和空间分块。AI 生图用于确定美术与纹理方向；玩家能绕行的房屋仍需真实几何、合理碰撞和侧后面。

### C. 扩展并接回完整剧情

按修理、送还、街坊互助、雨前准备、风险观察、雨后回访的顺序逐段验收。镜头、人物动作、交接物品、小游戏退出位置、对话和任务状态必须同时一致。多人联机不是获得参考生活感的前提，先把已有的街坊生活与单人剧情做扎实。

| 验收项 | 通过条件 |
| --- | --- |
| 连续行走 | 以正常游玩方式往返样板路线；停步、转向、跑步、贴墙时无明显瞬转、穿模和滑步 |
| 相机 | 逐个经过全部转角和门洞；观察目标清楚，头部不被遮住，地平线稳定；无突兀升空、穿墙或强制抢镜 |
| 角色 | 正、侧、背面近景均成立；交谈与递物期间人物有对象关系，手和物件不明显错位 |
| 美术 | 晴天、雨前、雨后使用同一套造型和材质规则；脸部、招牌和路线在阴影中仍可读 |
| 性能 | 在注明硬件、浏览器和画质的条件下，1080p 标准模式目标 60 fps，1% low 目标不低于 45；不能用静止镜头代替移动测量；低档稳定 30 fps 作为兜底目标 |
| 武汉辨识 | 首次测试先隐藏游戏标题，让玩家说出城市及视觉依据；记录真实理由，不能把写有“武汉”的字算成空间识别通过 |
| 剧情连接 | 四类小游戏、普通 3D 对话、记忆演出和结局均能正确返回世界、视角与存档，不重新发奖 |
| 内容容量 | 保留三名首次玩家实测主线 ≥15 分钟的要求；样板、自动通关或强制等待均不能代替 |

## 8. 本轮结论

可以用现有 Three.js 技术路线制作同类卡通街区和近身探索体验。主要投入在相机/角色控制、统一美术资产、可走空间和性能组织。本次完成参考拆解与制作规格；同等游玩手感必须用可操作样板验证，不能由几张图或一段录屏代替。


## 9. 下一步可实施的精品街巷空间方案

**范围：只改造修理铺→婆婆院门→早餐铺之间的两条现有空隙，保留中央 9 米主巷和全部现有任务 POI。** 下述空间已由 `src/street-composition.js` 实施并接入世界与地图，几何、坡面和通行检查见 9.3；实机游玩仍须按新构建单独验收，不能用示意路线替代。世界坐标按 `x` 向东增大、`z` 向南增大，地面常规顶面为 `y=.13`。

### 9.1 西侧工具巷：从工作台绕入院门

目前修理铺西墙在 `x=-18`，杂货铺东墙在 `x=-25`；含原建筑碰撞外扩后，两者之间有约 **6.7 米** 的空隙。这里可以形成第一个窄巷和折角，避免一离开修理铺就回到宽直中央道路。

### 9.3 实施约束与实际验收

- **先绑定真正可走的路。** `src/street-composition.js` 已实现实体工具棚、院墙、门架、坡道、扶手及面铺短巷，主任务已接入世界和 `heightAt`。施工后的 Node 检查使用真实 9 栋建筑、新版 11 棵树、主要家具、自行车、灯柱与棚顶数据，两段中心线按 .025 米间隔共采样 2,535 点，全部可走；所有分段通过原 `walkableSegment()`。证据见 [街巷几何报告](../output/qa/street-composition/geometry-report.json)。这仍不覆盖动画 NPC、全部散置小道具与真实相机；正常 UI、WASD 和实机画面继续另验。
- **保留自由路线。** 两条巷道都是真实可走的选择，地图使用同一份空间数据。现有自动引路继续按可达最短路线工作，不为录像强改任务路线；玩家可用正常键盘操作探索新巷。抵达与任务完成只以原 POI/剧情状态判断，不以“走过指定点”发奖或解锁。
