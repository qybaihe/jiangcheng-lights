# 《江城有灯》江风寻灯冒险体验

日期：2026-09-09。本文记录本轮设计意图、实装与分构建验收结果。

**当前状态：门楼、三站原地阅读、听风台与独立支线已实装。最终构建为 `index-SwoMhVuu.js`，98/98 纯测试通过；实机证据分属下列三个构建，不能合称最终版本全项通过。**

- `Bbg0aAAn`：34/34 浏览器操作检查，覆盖三站阅读、部分进度刷新、登台跳跃、重读和返回修理铺；台上有树遮挡江景的问题。
- `Bs6mbhbl`：将该树移到右侧后，采集 1920 × 1080 六机位；原生键盘实际上下完整坡道，130 个上行样本与 126 个下行样本覆盖 0.13–1.93 米。台上中央江景恢复；风筝朝侧与坡底近墙机位仍有不足。
- `SwoMhVuu`：再将风筝朝向西侧来路，实机复拍确认展开的燕子轮廓更清楚。与 Bs6 的源码清单对照仅 `src/adventure-scenery.js` 改变；没有把 Bbg 的 34 项操作检查冒称为在 Swo 重跑。

## 1. 玩家要经历什么

让玩家先望见一个值得抵达的地方，再通过门楼、侧巷和留言找到路，最后登上听风台，看见此前被屋檐遮住的江景。

这是一段发生在武汉里份生活中的小冒险：燕子路标引出好奇，风铃与邻里留言让探索有人的温度，真实可达的高处提供方向和回望街区的机会。普通阅读和交谈继续发生在 3D 世界，玩家能看到自己所在的位置和离开的路。

体验顺序为：

**看见远处的燕子风筝与灯 → 穿过中央门楼 → 在工具巷读燕子路标 → 到北侧风铃旁读留言 → 沿实际入口登上东北听风台 → 读第三段文字并回望江城。**

三次阅读应分别回答“往哪里走”“这条路与街坊有什么关系”“抵达后发现了什么”。文字内容以本轮实际剧情为准，不能只重复方向说明，也不以等待、强制慢速或重复点按拉长时长。

## 2. 本轮确认的场景主轴

| 场景节点 | 实施意图 | 玩家应当看到的空间变化 |
| --- | --- | --- |
| 中央架空门楼 | 给原本宽直的主街建立有厚度、有支撑的门槛；从门下穿行，屋檐和立柱组织视线 | 进入前看到门楼与远处线索，门下视线收束，穿出后出现新的路口或目标；门楼不能只有正面贴图 |
| 工具巷燕子路标 | 将已有窄巷变成有目的的探索入口；路标依附真实门、墙或支架，位于自然会注意到的位置 | 先发现燕子形状和方向，靠近才读清文字；转角后的出口有天光或下一处线索，不让整段路成为无内容的墙面 |
| 北侧风铃留言 | 建立第二个可以停步的生活节点，连接巷子与江岸；风铃、悬挂点和留言属于同一组实物 | 从狭巷进入稍开阔处，看到风铃与可阅读的留言；此处能再次确认听风台方向 |
| 东北听风台 | 已制作公共缓坡与平台；普通地面 y=0.13 米，台面 y=1.93 米，实际高差 1.80 米，坡度 1:8 | 沿真实入口上台后能望江，回头可见下降的坡道与来路；台上中央遮挡树已向右移开 |
| 远处燕子风筝与灯 | 提供贯穿路程的视觉目标；燕子轮廓、线的方向和灯的暖色与武汉江风及邻里生活联系起来 | 在部分街面机位只露出目标的一部分；越接近越能辨认，抵达时与平台、江岸共同成景 |

东北听风台替代此前讨论的婆婆楼北侧外廊。新空间应避开原有居民与备用电池通道，原主线、居民位置和已存在的任务关系继续使用。晴川里仍是虚构拼合街区；本轮新门楼、听风台与留言不作为真实历史遗址介绍。

## 3. 构图与材质要求

### 3.1 远处有目标，近处有入口

门楼、屋檐、树冠和院墙应控制目标露出的比例，形成“看见一点—暂时遮住—换个角度再出现—抵达”的过程。不能在第一处入口就完整展示所有节点，也不能一直遮住目标、让玩家只能依赖箭头。

每个主要机位应有可区分的三层：近处门框、墙角或栏杆；中间可走路线与玩家；后方的灯、风筝或武汉江景。听风台登台前后的差别需要来自真实位置和高度变化，不能只靠拉远相机或切换一张图片。

### 3.2 温暖的色彩仍要有清楚的明暗

沿用暖米色墙、青灰瓦、墨绿木构、砖红局部和草绿植物。门楼内侧与窄巷可以更沉静，转角出口、文字节点和台上灯光作为温暖焦点；脸部、台阶和通道边界在阴影里仍须可辨。

大面积地面与墙面要有色阶差异。细节集中在玩家会停留的路标、风铃、灯、扶手和接触位置，避免所有墙面、天空和地面都以同样亮度争夺注意力。

### 3.3 武汉通过空间关系出现

里份门楼与窄巷建立街坊生活尺度；江岸、轮渡、江汉关轮廓与风筝组成远景。听风台的回报是从街巷走到望江位置，地标不应为了显眼而全部挤在眼前。招牌和标题之外也应保留可识别的城市线索。

实装支线标题为“追着江风找灯”。下列坐标为世界空间 `(x,z)`，与当前 `src/adventure.js` 一致。每站六句，共十八句，以一张逐步露出的借灯条串联。

阅读保持当前 3D 场景；三站操作报告及第一人称重读均证实没有进入影片或切到另一张背景。第一站阅读期间真实拖动 200 像素，朝向改变 0.489 弧度，角色位置与跳跃次数不变，3D 帧持续更新。

进度只保存在 `state.adventure.found`，按以上顺序收集。提前到达后续站点只显示环境提示；已收集站点可重读。只有读到末句才登记，半途退出不计数；重读、未知 ID 与跳序尝试不产生重复成果。地区标题仅作提示，没有等待或进度副作用。

Bbg 实机已确认半途退出、完成后恢复控制、第一站完成后刷新恢复 1/3、全部完成后重读不重复。**3/3 全完成后的再次刷新尚未单独实机验证。** 主线 flags、supplies、lore 在三站完成后仍为空，且可以返回修理铺开启原地 3D 主线引子；这不等于本轮已重走全部居民、物资和风险点。

## 5. 可走空间与相机要求

听风台、入口与栏杆的可见几何要和真实碰撞一致。玩家必须能从公共路径正常到达，沿入口上行、停留、回头和返回。台面不能只是景物，楼梯也不能仅靠贴图表现。

地面高度、平台边缘和入口衔接使用一致的规则。现有单值地面高度不能自动代表同一水平位置的上下两层；若有架空的可走层，需明确层间通行语义，防止人在下方突然跳到台上。平台基座封闭时，地图和引路也应承认其不可穿行。

门楼梁底、檐口、灯与路标须检查站立和跳跃净空。栏杆阻止角色从平台侧面直接穿出；正常走跑不能穿入实体台阶或从侧面登上平台。若提供自动引路，应实际走入口，不能直穿基座。

沿用已修复的手动观察语义：拖动和按住停顿时玩家掌握方向，释放后再平缓避障。门楼、平台转角和台阶需要重新检查近墙缩距及主角淡出，不能只用无遮挡旧街的镜头证据代替。普通阅读时应能辨认人物、对象与出口。
