## 1. 先承认这版到底改什么

不是增加更多催泪台词，而是让已有的好细节有机会起作用。

| 现版问题 | v3 决策 |
| --- | --- |
| 回家先是空店、旧物、字条，之后才解释外公在世 | 序章直接接到外公的活人电话；“药吃了／你吃饭没”交代近况，不卖病危悬念 |
| 动作、人物对白、旁白轮流讲同一个意思 | 人物只说眼前事；动作写给演员/镜头；删掉全部主线解释性旁白配音 |
| 每位街坊都像在劝阿遥领悟人生 | 婆婆问工作、留旧画；蔡姨加葱、收饭盒；周伯话少，问往哪走；小许忙工作但也会拿错杯子 |
| 四张连续记录私人谈话的照片不可信 | 改成一张童画裂开的四片，用可见拼合线索完成任务 |
| 周伯故意把照片藏到做完任务才许看 | 直接说外公后来回店了；自然托带旧照，电话打断，阿遥自己先收好 |
| 结尾先读长信，再看同一件事，再总结几次 | 只留照片背面一句记事；CG 给出第一次完整群像；回 3D 用一通家常电话落地 |
| 大雨突然开始，已有积水又像来自尚未下的雨 | 午后阵雨 → 傍晚短晴 → 晚间预警与提前准备 → 已有低处积水 → 新一轮雨 → 稍后确认通道 |

原运行稿有 189 条正文、6,596 字符，其中人物/字条 139 条、4,158 字符，旁白 50 条、2,438 字符。v3 对白约 1,700 字符，具体计数见 `output/script-review-v3/script-metrics.json`。动作说明不再默认送去 TTS。**不以删字百分比代替自然度，也不把配音时长当玩法容量。**

## 2. 每一场新增什么，而不是每场都更悲伤

| 场次 | 玩家原来以为 | 这一场真正新增的事 | 结束时做什么 |
| --- | --- | --- | --- |
| 序章 | 回来办几件事，明天走 | 外公仍会给自己留“作业”，这间店还按老习惯用着 | 玩家自己开门、修好收音机 |
| 婆婆 | 她只是小时候认识的邻居 | 自己曾睡在她的竹床上，她连一张歪画也收着 | 接下她已决定的社区联络安排 |
| 蔡姨 | 外公什么饭都会做 | 红盖饭盒的豆皮出自蔡姨；她记得旧口味，也接受新口味 | 领取并交回物资，再提醒她吃饭 |
| 周伯 | 外公一直理所当然地守着铺子 | 他也动过离开的念头，是自己想好先回去；周伯只托另一边 | 自然接过旧照，确认社区联络 |
| 社区 | 自己在逐个跑任务 | 这些人正在共同完成同一晚的事，准备和到达要分开 | 核包、两处当场报告、返回核实 |
| 尾声 | 那晚大人只是来店里修东西 | 大家让店重新开门，也给十岁的自己留住了写字的地方 | 给外公打完电话，约下一顿过早 |

三位街坊可以自由拜访。表中是阅读顺序，不把上一行的经历当下一行的必备前提。情绪不每场连续上扬：认出饭盒后可以笑，托箱后回去办事，最后才把童年的自己接进来。

## 3. “只有 10 秒”不是一个调长参数就能解决

只读实测和源码见 [CG 审计](../output/script-review-v3/cg-audit.md)。

- 现在 `playFilm()` 播放的 `arrival.mp4`、`ending.mp4` 各约 10 秒。
- 独立旁白 `prologue.mp3` 为 21.1 秒，`letter.mp3` 为 24.1 秒；当前代码在视频结束时暂停旁白。因此旁白会被短画面截断。
- 8 张 `story-v2-cg-*` 是玩家翻页的静态回忆图，没有 10 秒统一倒计时。
- 13 秒三镜样片与 78 秒旧方案均没有成为当前游戏的完整序章。

v3 不把旧视频循环三遍，也不冻结最后一帧等长旁白念完。每场先有一个完整事件，再把它拆成相应镜头；每个镜头要带来新空间、新信息、动作结果或人物反应。**单次 Seedance 素材长度与剪完的整场长度是两回事。**

## 4. 新 CG 结构：先完整，再精细

全部目标时长是编排估计，不是现有成片规格。动作按自然速度拍，试片后调整。

| 场次 | 目标 | 内容结构 | 回到游戏的精确位置 |
| --- | --- | --- | --- |
| 序章完整 CG | 28–34 秒，拟 32 秒 | 武汉岸线 → 回家钥匙 → 里分生活 → 认出旧门、来电 | 门前接电话，由玩家开门；现在时对白在 3D |
| 婆婆回忆 | 约 28–36 秒 | 端面、允许接孩子 → 时间经过 → 竹床午睡、洗手再抱 | 阿遥：“我记得。那回醒了，扇子还在响。” |
| 蔡姨回忆 | 约 28–36 秒 | 灯照清零钱 → 多年后留饭 → 红盖饭盒 | 阿遥认出白点，而不是再次解释借灯 |
| 周伯回忆 | 约 24–30 秒 | 不确定去处 → 问能否托箱 → 外公选择先回去 | 周伯直接回答后来还是开了 |
| 小许毛巾 | 可选静态 CG，玩家自行推进 | 看到毛巾才问 → 过去递毛巾 → 回当前小屋 | 不塞进强制办事流程，不专门为它拍长视频 |
| 尾声过去 CG | 35–45 秒，拟 40 秒 | 看清书包 → 搬桌到窗边 → 留饭、铺布 → 孩子坐下 → “还在这里” | 挂钟声切回现在的照片和外公来电 |

### 序章 32 秒的可剪辑镜头单

| 镜号 | 暂定剪辑位置 | 画面信息 | 声音 / 转场 |
| --- | --- | --- | --- |
| P01 | 0–6 秒 | 栏杆内看汉口；江汉关与宽江面建立武汉和尺度 | 船机、风、水；不配城市介绍 |
| P02 | 6–10 秒 | 船内手心的一把旧钥匙，让返乡有具体目的 | 钥匙圈碰响；不露脸、不锁定男女 |
| P03 | 10–15 秒 | 同一岸线更近，注意力从手回到目的地 | 硬切；第一段试片到这里，**不是完整序章** |
| P04 | 15–21 秒 | 里分巷口，街坊收竹椅，锅盖响 | 用生活声跨切，不假装从船飞进巷子 |
| P05 | 21–28 秒 | 阿遥经过门洞，认出旧修理铺；脚步停下 | 以所选男女角色匹配服装/步态；需要独立角色版本或真正通用机位 |
| P06 | 28–32 秒 | 门、钥匙、手机来电；接到实时镜头 | 来电信息后期叠加，不让模型写汉字；切 3D 接电话 |

**本轮动态试制只提交 P01–P03 的一条 15 秒素材。** 这三个镜头在同一艘船上，使用统一首帧；先检验动漫画风、钟楼结构、手与钥匙，再由用户看样片。P04–P06 仍待制作，不把前半场标成已经完成的 32 秒序章。图像使用用户已授权的 Image2 接口；视频使用项目原有 Ark Seedance 2 接口，不创建额外 ChatCut 项目。

### 尾声 40 秒的动作逻辑

| 镜号 | 暂定时长 | 真正发生的事 |
| --- | ---: | --- |
| E01 | 4 秒 | 照片里的补丁书包，转到过去同一物件；不是幽灵或穿越设定 |
| E02 | 8 秒 | 两人抬工作台过门槛；周伯问靠哪边，外公留出孩子的位置 |
| E03 | 7 秒 | 桌子只落地一次，试稳；蔡姨将饭放另一张柜台，婆婆随后铺蓝布 |
| E04 | 6 秒 | 孩子从里屋拿本子出来，坐到刚空出的地方；不是坐着被搬桌 |
| E05 | 9 秒 | “明天还在这里写？”“还在这里。”孩子低头继续，大人放轻声音 |
| E06 | 6 秒 | 外公抬凳子不拖地；一个字写完，以挂钟声回到当下 |

现有 `ending-reopen` 与 `ending-lamplit-child` 只提供人物、灯、书包与构图锚点。搬桌、孩子入场、抬凳这些动态尚未生成；不得把两张旧图之间的溶解当成这些表演都已完成。尾声先等用户认同主稿再排生产，避免口型、台词和时长反复重做。

## 5. 童画交互的明确内容

这是**一张画裂成四片，拼位置**，不是四次私人谈话的时间排序。保留现有四卡交互和通关结果 `granny`；后续调整展示、判定语义及画卡素材。

- 完整画是十岁阿遥送婆婆的院落日常：角落没开门的修理铺、婆婆的饭桌、阿遥的作业本、竹床与蒲扇。画中人比例歪一点，碗很大，签名认真。
- 画的上半部是一条连续门框轮廓；下半部有贯穿两片纸的桌沿；中间有一根转折形铅笔涂线。三条视觉线与纸边共同限定位置，不能靠猜主题排序。
- 兼容旧四 ID：`close` 左上、`bowl` 右上、`talk` 左下、`open` 右下。ID 不决定玩家能否理解线索，四片正面必须实画后盲测。
- 操作结果不直接播放结尾合影，成人当年的对话由婆婆讲述后进入 CG；不暗示孩子画下了不在场的私密谈话。
- 本轮只有规格，没有生成四张画卡，也没有宣称拼图已经改好。

## 6. 地方性与连续性锁定

1. **武汉不是地标拼盘。** 序章江汉关与汉口岸线；大桥另在河岸远景，保持钢桁架而不是斜拉/悬索桥。日常用过早、豆皮、葱花、竹床、里分门洞、轮渡支撑地方感。晴川里为虚构街区，不声称路线复原。
2. **外公在世。** 手机当下声音保留生活底噪。没有遗言、追悼滤镜、孤零零遗像、病危倒数。
3. **两盏灯分开。** A 绿边便携灯还给蔡姨；B 铜圆底、细弯颈台灯留店。结尾不让 A 或已还的收音机回到桌上。现版灯具规则优先于旧导演案的“两盏同款”。
4. **年龄分开。** 大部分过去约十五年前；蔡姨初摆摊可再早几年；小许仅约一年前。不是所有人统一变二十岁。童年阿遥背侧与短发不指定当前男女选角。
5. **色彩明亮。** 暖米白、青玉、砖红；回忆不统一加棕黄滤镜。难处可以发生在干燥、有光的地方。
6. **天气与居民去向连续。** 人物已去社区后，不又在原 POI 接着做原动作；恢复游玩说明公共主巷确认可走，低处不随雨停自动解禁。

## 7. 台词通过后，怎样接回代码与配音

| 当前模块 | 需做的改动 | 验收边界 |
| --- | --- | --- |
| `intro` | 替换为实时电话，新增开门/试机衔接与天气卡 | 不误读外公去世，30 秒内知道回到谁的店 |
| `granny` / `grannyMemory` | 缩短；照片任务改童画拼合 | 线索可见、唯一解、现在/过去边界准确 |
| `chefIntro` / `chefMemory` | 路线移手账，保留交接动作与饭盒认物 | 拿齐不算交付；准备不算送达；三物都有最终去向 |
| `dock` | 不故弄玄虚；自然交信封 | 提前自由拜访不剧透集体重开店 |
| `community` | 简化汇报；毛巾成为可选触发 | 主线不因没看毛巾卡住，旧照解锁和回放另定触发 |
| `prepared` / 风险 POI | 简短委托；每处当场消息与明确回执 | 不等凑齐两个风险才报告；看不清可如实报告 |
| `checked` | 不重复两次报告，核对真实到达 | NPC 状态、物资和天气同时更新 |
| `ending` | 去长信及重复总结，过去电影后接现在电话 | 结尾语音不继续铺在童年 CG 上 |
| `playFilm()` | 新章节资源表、明确音画时间线 | 任何旁白/对白不被短视频尾截断；不循环撑时长 |

旧 `SAVE_KEY`、主要 flag 与领取/交付前置不改。已有存档不清除。旧句 ID 中语义相同者保留，新增句分配新 ID；不能按数组下标决定过去/现在。

### TTS 不是按页重新全量烧一遍

- 主角保留男女两个版本；长辈声线维持已建立的角色档案，先测试新短对白的自然度。
- 对最终句 ID、文本、角色/年代、音色参数做哈希。文字或音色变了才生成，完全没变且适用者复用。删除的旁白不放入新 manifest。
- 先试序章 4 句、婆婆 2 句、蔡姨 2 句、周伯 2 句、尾声 4 句；确认“聊天”而非播音腔后批量。
- 大人正常说话；“哪有那么大本事”平常说，不拉成哭腔。停顿放在音轨时间线上，不在每句合成音频前后塞长静音。
- 演出说明不配音。短问短答可放同一画面逐句突出，不把每行文字机械变成一个强制点击页；下一句/退出仍立即打断当前语音。
- 新影片原始音轨按试制要求保留或移除，正式成片单独管理 BGM、环境、对白；不会同时叠两条配乐。游戏里开口时音乐让出空间，关闭影片恢复正确场景。

## 8. 这次你主要验收什么

- [ ] 读完序章，知道自己是谁、为什么回来、外公现在在哪里、第一步要做什么。
- [ ] 把对白念出来像聊天；不知道谁说的，也能从口气和正在做的事辨认几位街坊。
- [ ] 婆婆、蔡姨、周伯任意换顺序，都不用假装已听过上一段。
- [ ] 不靠旁白解释，能指出一件打动自己的小事；不是每场都强行“原来如此”。
- [ ] 看到结尾才把自己的童年与街坊们接起来；此前线索有铺垫，又没有提前把答案讲完。
- [ ] 想略过 CG 时仍能推进；电影长是因为有事件，不是灯慢慢亮了十几秒。
- [ ] 认可主线对白与 CG 分工后，再进入全套视频、配音和游戏接入。

真实首次游玩容量、武汉本地识别、应急专业核验以及性能回归仍属后续游戏验收，不因为交出剧本或画面试片就自动通过。
