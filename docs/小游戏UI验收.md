# 小游戏 UI 专项验收

入口为 `node tests/activity-ui.mjs`，默认连接 Vite `http://127.0.0.1:5173`，可用 `GAME_URL` 改地址。测试在新建浏览器上下文里拦截专用 HTML，导入正式连线、相册、装包、情境判断组件和共同样式，放进正式面板结构；不导入 `main.js`、不启动 3D 世界、不读写用户存档。它验证活动组件，不能替代完整游戏通关、真实世界背景下的观感或主界面对话接续。

## 验收标准

- 连线、相册、应急包、情境判断各测 1440 × 900 桌面和 390 × 844 手机，共 8 个场景。
- 每个场景保留默认、错误、成功截图，共 24 张。页面、面板和活动正文均无横向溢出；需要纵向滚动的内容仍能正常触达。逐个滚动检查可操作控件不被遮住、有键盘焦点，手机点击目标不小于 44 × 44 像素。
- 1440 × 900 下，相册和应急包的默认与成功主按钮无需滚动即可看见。控件可见性同时检查视口、实际裁剪祖先和命中位置；固定遮罩不受普通流中零高度 `body` 的边界裁剪。
- 通过真实 Enter／Space 按键转动铜线、上下换序、选择与替换物品、重试情境判断；不修改组件内部答案。重新绘制后焦点仍留在同一零件、物品或相片上。
- 连线另检查撤回、复位与方向键移焦；应急包另检查第五件之后不能继续增加、从包内取出物品后焦点回到桌上对应物品。
- 错误提交显示可读解释，活动保持打开，允许继续修改并成功。错误不调用 `onComplete`。
- 正确答案先停在成功界面，只有按下 `[data-activity-continue]` 才推进。重复提交正确答案不会提前推进，多次触发继续只调用一次 `onComplete`；情境判断传回正确选项。
- 情境判断的错误解释和成功继续按钮，必须在测试主动滚动之前已经完整处于面板与视口内，不能靠截图脚本滚动来掩盖反馈留在屏下的问题。
- 每个独立场景的 `localStorage` 始终为空，页面错误单独记入报告。浏览器及上下文在 `finally` 中关闭。

## 证据与范围

截图和结构化报告写入 `output/qa/activity-ui/`。默认报告名为 `report.json`，可用 `REPORT_NAME` 为复验另存；带时间的报告保留每次运行结果，失败截图也保留。报告包含视口、组件和公共样式的 SHA-256、逐项布局与操作证据、页面错误、每个场景的状态及浏览器关闭标记。可用 `ACTIVITY_FILTER`、`VIEWPORT_FILTER` 或形如 `CASE_FILTER=mobile:circuit,desktop:memory` 的组合缩小复验范围。

2026-09-08 的统一全轮报告为 `final-report.json`：**8 / 8 场景、90 项断言通过**，页面错误为 0，24 张截图全部生成，浏览器正常关闭。逐图审查确认手机连线端子完整显示，情境判断插画的黑色三角消失；桌面相册和应急包的默认、成功操作区均在首屏内。

首轮证据保存在 `first-pass/`，包括手机连线正文横向外伸 3 像素的布局失败、开放 SVG 折线默认填黑的视觉问题，以及桌面相册／应急包按钮需要滚动的原图。`refinement-report.json` 保留一次测试实现误报：新的裁剪判断把固定遮罩外的零高度 `body` 算入了裁剪链；修正判断后才得到上述全轮通过，未以修改页面样式来迁就错误断言。

最后一轮针对成功态文字可读性、连线反馈文案以及情境判断反馈自动进入视野进行复验，结果为 `readability-report.json`：连线、应急包、情境判断的双视口 **6 / 6 场景、70 项断言通过**，页面错误为 0，专项浏览器全部关闭。该轮没有改动相册，相册沿用全轮的两组证据。更新后的物品和选项文字已逐图确认可读，应急包成功后不再显示可取出的提示；连线反馈改为“输入端已经连到喇叭”，避免把备用零件也描述为全部接通。

最终索引 `latest-evidence.json` 汇总 **8 个场景、24 张默认／错误／成功截图**，为每个场景注明来自哪轮报告，并检查适用的组件及共同样式 SHA-256 与当前源码一致。它是逐场景证据索引，不是额外执行的一轮测试；全轮和补测次数不能简单相加为独立覆盖量。上一版成功态截图保存在 `before-readability/`。

手机情境判断在测试未主动滚动时，错误解释纵向范围为 765–815 像素，成功继续按钮为 748–806 像素，均完整位于约 18–826 像素的面板可见区域。桌面相册和应急包的默认、成功按钮首屏断言仍通过。

代表证据：`desktop-memory-default.png`、`desktop-pack-success.png`、`desktop-choice-success.png`、`mobile-circuit-success.png`、`mobile-choice-error.png` 与 `mobile-choice-success.png`。这些仍是隔离组件界面，未把它们算作真实世界中的通关截图。生产完整流程另见 `output/qa/ui-refinement/walkthrough/browser-report.json`；该流程基于最后一轮成功态样式和自动滚动微调前的构建运行，最终 UI 细调由本专项补测覆盖。
