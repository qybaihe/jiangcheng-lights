# 《江城有灯》剧情与任务链路

更新：2026-09-08。本文件记录已经落地的剧情、状态约束与恢复行为；不固定视频总长，不以看完长视频代替玩法容量。具体运行以 `src/story.js`、`src/dialogue-presentation.js` 及主界面的交互调用为准。

## 故事的递进

阿遥回来时把送东西看成一件短差事。修好收音机，让她重新动手；进入三位街坊的生活，让她意识到旧物之所以被留下，是因为有人愿意关心别人。等到她自己把关照名单、热食与联络安排带回社区，再把风险观察交给合适的人，结尾的旧信才有了当下的对应：外公曾经接受过这份帮助，她今天也在学着让帮助发生。

**情绪依次是熟悉中的疏离、愿意听、愿意接受、有人同行、能一起做事、被照顾的关系得到确认。** 不要求每段都比上一段更煽情；回忆说清一件事，就把时间交还给 3D 世界中的行动。

三段记忆各增加一条信息：

| 回忆 | 新增信息 | 关键动作 | 对今天的启发 |
| --- | --- | --- | --- |
| 林婆婆：一碗面的位置 | 外公也会遇到难处，别人不必先知道全部原因，便可以问一句、留下一个位置。 | 敲门、推碗、坐下、说出难处。 | 先问独居街坊需要什么，再带着已经确认的关照安排去社区。 |
| 蔡姨：留着一口热的 | 外公曾帮她修炉子、送灯；他不是永远给予的那个人，也可以接受回馈。 | 蔡姨用熟悉的修炉子往事化解他的拘谨，挪出一只凳子。 | 接受分工。阿遥领取并交接物资，蔡姨负责分装，社区同事负责取送。 |
| 周伯：等最后一个人 | 外公一度想离开，周伯没有替他决定去留；问过之后，才一起承担箱子的重量。 | 征得同意、共同托箱、并肩走回巷口。 | 尊重别人的决定；愿意帮忙也要先沟通，看到风险交给合适的人。 |

保留热干面作为武汉生活的连续意象，但第二段不再重复「谎称多煮一碗面」的情节。第三段也不揭示谁已把修理铺重新布置好，只把外公送到巷口；重新开门的完整真相留到结尾。

外公当下健在，在外地休养。结尾的手机语音、阿遥的回应和她想多住几天的决定继续发生在 3D 修理铺里。

## 玩家怎样走完这条链路

地图、任务和对白使用同一份进度。修好收音机后，三位街坊允许自由拜访；任务提示给出一条推荐顺序，不把推荐顺序误当玩家已经完成的经历。三段帮助全部确认后，才进入社区准备。

| 节点 / 状态 | 触发条件 | 玩家实际行动 | 完成后确认的帮助或变化 | 离开与重进 |
| --- | --- | --- | --- | --- |
| 回到修理铺 / `received` | 尚未读完开场留言 | 在 3D 修理铺阅读外公留言，认识待修收音机、旧灯与手电。 | 知道三件委托属于谁，开启修理。此时不能自行拿走街坊物资。 | 读到一半离开，重进从开场第一句开始；全部读完才保存 `received`。 |
| 修好收音机 / `radio` | 已 `received` | 旋转铜线，连通实际电路。 | 收音机有声音，三位街坊的正式拜访可进行。 | 旋转中途离开只重置本次谜题盘，不重播已经完成的开场；通过后无需再修。 |
| 婆婆的当下对话 | 已 `radio`，未 `granny` | 送收音机、听贴纸的来历、了解婆婆的日常关照。 | 进入四张生活照片的排序。没有提前获得关照名单完成状态。 | 对话或排序中断，重进可重新完成；不产生两份收音机或两份奖励。 |
| 婆婆的回忆 / `granny` | 排序正确 | 进入回忆，再回到 3D 听婆婆说完今天与陈姐的安排。 | 一份已与社区沟通过的关照名单。阿遥负责带回核对，不自行决定谁要去哪里。 | 回忆和后续对话全部结束才记录 `granny`；之后可在手账重看，进度不重复累加。 |
| 蔡姨的委托 / `chefRequested` | 已 `radio`，尚未接到该委托 | 在过早铺归还灯，问清保温箱、水、电池的主人、位置与用途。 | 才获得领取约定物资的权限。 | 未谈完时不算接受委托；重进仍能确认安排。旧存档早取的物资会保留，不要求丢弃重拿。 |
| 领取三件物资 / `supplies` | 已 `chefRequested`，该物未收过 | 去西侧杂货铺、南巷和北边雨棚，各领取一次。 | 随身持有待交接物资，任务提示具体指向下一件缺少的物品。 | 每领取一件立即保存，可任意次序；重进只找缺少的物品。已收齐仍没有 `chef`。 |
| 蔡姨交接与回忆 / `chef` | 已接委托，三件均收齐 | 回过早铺把物资放上干燥桌面，听逐项核对、分装与社区取送安排，再听旧灯的回忆。 | 确认热食准备、饮水、电池可由社区统一交接。阿遥带回消息，不额外独自运送。 | 本轮对话完整结束才确认 `chef`；中途离开保留三件物资，重进继续完成交接流程。完成后 `supplies` 保留为交付记录，不能重复领取。 |
| 周伯的当下与回忆 | 已 `radio`，未 `dock` | 还手电，在安全公共通道听他讲外公抱着工具箱的那一天，接过旧信封。 | 周伯明确与小许约定协助联络街坊。信封的具体内容仍未展开。 | 对话中断不提前解锁社区联络完成状态；重新拜访可完成。 |
| 周伯的判断 / `dock` | 周伯对话结束 | 选择留在安全位置观察、联系社区确认通道。 | 保存信封与周伯联络安排；三人帮助全部齐备时指向社区。 | 错选给出原因，不扣物资、不推进；离开后可重新完成本段，正确选择才记录 `dock`。 |
| 社区核对 / `prepared` | `granny`、`chef`、`dock` 全部完成 | 带回名单、热食交付安排与联络消息，选择五项基础应急物资。 | 应急包核对通过。小许安排人员取送和协助居民；此时是准备完成，还不能说大家已经到达。 | 提前来访只得到下一步提示，不跳过街坊；选择正确时立即记录 `prepared`，随后说明中断不抹掉准备成果。 |
| 两处安全观察 / `riskWater`、`riskCable` | 已 `prepared` | 从干燥安全位置看江边低处入口和配电箱旁积水，选择避开、记录、报告。 | 两个独立观察记录；任意一处可先完成，提示按真实完成数显示 0/2、1/2。 | 每处正确选择立即保存；不涉水、不靠近电气设备，也不以跟随别人作为安全依据。已记录地点不重复记功。 |
| 回社区报告 / `checked` | 已 `prepared`，两处均已记录 | 把位置与风险告诉小许，听她核对街坊和物资的实际到达情况。 | 小许接手联系专业人员；此时才确认婆婆、热食与周伯已经到达或报平安。天气和街坊去向进入雨前收束。 | 只做完观察还不能直接结尾；报告对话结束才记录 `checked`，重进不虚构已报平安。 |
| 修理铺结尾 / `ending` | 已 `checked` | 沿干燥主巷回室内，展开旧合影与信，看见街坊曾怎样替外公把门开起来；听他现在发来的语音并回应。 | 外公曾被大家照顾的真相，与玩家刚完成的互助构成呼应。阿遥决定多住几天。 | 结尾对白结束才记录 `ending`；中断可重新读。完成后继续自由走访和收集，不重开主线任务。 |
| 江城拾光 / `lore` | 任意阶段 | 阅读六处城市生活记忆。 | 独立收集，不替代任务、不提前赋予能力。 | 已收项可重读，重复不会增加数量；旧存档收藏继续有效。 |

现有对话进度按段落完成保存，不保存到每一句。每次重新进入会从该未完成段落开始，这一点应在实际首次试玩中观察是否造成负担；不得把重复阅读时间计作新增玩法设计。

## 城市细节与结尾的保护

- 修理铺：歪一点的「陆记修理」木牌、蓝布、旧收据、童年轮渡票，让回来的人先辨认出熟悉的生活。
- 婆婆小院：木窗、竹凳、收音机和一碗热干面。照片排序只讲敲门到坐下的那一天，不把最后的重开店结局提前当答案。
- 过早铺：即使阿遥傍晚回来，蔡姨也愿意给她开一锅；芝麻酱、豆皮、炉子和旧灯把人情落在具体的生计里。
- 码头：等末班船靠稳、熟悉的手电和隔江相望的日常。河岸拍摄/探索位置始终是安全公共通道。
- 社区：谁负责联络、谁装箱、谁取送、谁核对，逐项有来处；公益主题通过完成的分工呈现。
- 自由拾光的 `photo` 现为阿遥童年与外公的轮渡合影。它不再叙述修理铺重开和街坊搬工作台，因此可以从开场就自由收集。
- 结尾旧信封里的重开店合影是另一张照片；洗窗帘、搬工作台、留花和留饭的完整组合仅在结尾揭示。

江汉关、长江大桥、热干面、轮渡与汉口建筑提供相互独立的武汉线索。晴川里仍是原创虚构空间，地标经过艺术压缩；剧情不冒充真实街道复原、不虚构具体历史洪灾或真实居民经历。

## 3D 对话与回忆的边界

普通现在时对白、物资交接、小许核对、外公的字条与当下手机语音始终留在所在 3D 场景。只有角色明确进入过去时切到记忆层：

| 对话键 | 当前回忆区间（左闭右开） | 回到 3D 的第一句 |
| --- | --- | --- |
| `grannyMemory` | `[0, 8)` | 阿遥：「外公从来没跟我讲过。」 |
| `chefMemory` | `[6, 14)` | 阿遥：「原来这盏灯，不只照过您的摊子。」 |
| `dock` | `[9, 15)` | 周伯：「后面的事，都在这个信封里。先把今天的安排办妥，回到屋里再慢慢看。」 |

区间由唯一的文字锚点计算，不把上表数字写入切换逻辑。蔡姨的新返回句不预设玩家已经见过婆婆；任意顺序拜访仍说得通。手账中的主动回放可以整段进入回忆层，不改变主线状态或完成时间。

预渲染电影只承担必要的景别和情绪变化。按信息量剪辑，不再为凑固定总长延长亮灯或水纹；它不能覆盖玩家刚在 3D 中展开的现在时对话。

## 对主界面的数据接口

保留 `SAVE_KEY = 'jiangcheng-lights-v1'`、版本号 1 与全部既有 flag 名称。

`objective(state)` 保留 `title`、`desc`、`target`，新增：

| 字段 | 用途 | 例子 |
| --- | --- | --- |
| `step` | 稳定的任务阶段标识 | `deliver-supplies`、`observe-water`、`report-risks` |
| `action` | 玩家此刻要做的动作类别 | `visit`、`collect`、`deliver`、`observe`、`report` |
| `location` | 与目标 POI 一致的地点名 | `蔡姨的过早铺` |
| `hint` | 具体操作、分工和安全距离说明 | 「收齐不等于交付；回到过早铺完成交接……」 |

`isAvailable(state, poi)` 对已接到蔡姨委托且尚未收取的物资返回真；对未完成准备的风险点返回假。居民拜访仍可自由进行，由对话分支解释下一步。`availabilityHint(state, poi)` 提供未获领取约定、已持有、已交付或未准备观察等情况的短说明。界面必须在 dispatch 之前据此拦截无效物资领取，不能一边拒绝状态变化、一边显示「已收好」。

`act` 额外守住关键状态前置条件：收音机需要开场完成；三位街坊正式结果需要修好收音机；蔡姨交接需要约定与三件实物；社区准备需要三份帮助；观察需要准备；报告需要两处观察；结尾需要报告。此检查不把拜访顺序锁成单线，也不加入等待时长。

## 首次试玩的耗时记录

新增可选存档字段：

```js
milestones: {
  received: 42.6,
  radio: 116.2,
  // 首次合法获得其他 flag 时继续记录累计 state.seconds。
}
```

数值是主界面累计的游玩秒数，不是 Unix 时间，也不是自动推测的人类首次体验时长。首次获得 flag 时才写入；重看记忆、重复触发和无效推进不覆盖记录。相邻完成时间可用于分析某一段耗时；三位街坊允许乱序，应按实际时间排序再分析。

旧存档没有 `milestones` 时返回空对象，不根据已有 flag 伪造完成时间；后续新完成的部分才开始记录。读取会去掉非数字、负数和没有对应完成 flag 的里程碑，保留真实的已完成状态。库存和收藏去重，避免旧记录中的重复项误触发三件物资交接；旧版在蔡姨委托前已经取得的合法物资继续保留。

正式验证玩法容量仍需真实首次试玩：至少记录每位玩家的版本、是否提前读过剧情、路线、谜题尝试、离开/重进、总耗时及里程碑。脚本点完对白的时长或静帧/影片长度，都不能作为 15 分钟可玩容量已经通过的证据。
