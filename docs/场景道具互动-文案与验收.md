# 场景道具互动 · 文案与验收

> 本文保留内容契约与设计检查项。v1 的实际操作为 **F** 使用道具，读报的“收好报纸”同时起身；接入前的架构审查是历史风险记录。实测结果和交付入口见[道具互动 v1 交付与验收](/Users/baihe/Documents/ChatGPT/腾讯云游戏开发大赛/docs/场景道具互动-v1-交付与验收.md)。

## 1. 阅读口径

- 《晴川里街坊小报》是游戏内虚构刊物。每期页眉保留“游戏内虚构社区小报 · 非真实新闻或实时通航公告”，不冠真实媒体名称，不编具体日期、真实船期或灾情数字。
- 数据独立存放在 `src/newspaper-data.js`，导出冻结的 `NEWSPAPER_EDITIONS`。两期稳定键为 `beforeRain`、`afterRain`，每期恰有三则 `news`、一则 `advert`、一条 `evidenceHint`。
- 每期以及每条新闻/广告都有 `id`、`headline`、`deck`、`body: string[]`。期刊另有 `title`、`issueLabel`、`fictionNotice`。正文逐段呈现；页边暗示用普通小字，不标成“关键线索”。
- 雨前号在雨前、雨中保留；只有本周目已经收好雨后通行消息，即 `postlude` 成立，才换雨后号。`ending` 单独成立不等于雨已停；画面关闭雨粒子也不等于雨已停。
- 小报只补充武汉日常：过早、轮渡、饭盒、旧广告。雨前暗示仅是工作台一角的作业本；雨后暗示仅是搬桌留言里的不同笔迹。不提真结局条件，不提前解释旧照片，不把外公写成故人。
- 小报中的蔡姨短句是虚构报刊的转述，不加入冻结的主线对白表，也不自动播放或生成对白配音。
- 读报、借车、坐下、乘船是自由探索动作。主线台词、物资、委托、风险报告、毛巾回忆、结局选择、画廊解锁均保持原有入口。

| 雨中渡口 | 查看停航告示 | 这会儿停航。到棚子里歇一歇，等渡口更新消息。 |

“坐一趟轮渡”若实现的是从本码头出发、环游后回港，始终用同一说明，不写成已抵达现实汉口或武昌。椅子、桌子、报纸应在同一组可见道具中；按钮名称应指向当前能做的真实动作，不以弹一段说明替代动作。

## 3. 体验验收清单

### 借车

1. 步行接近实物才出现借车提示；按 F 或点按钮后人物与自行车发生可见绑定，骑姿不等于站着加速。
2. 相同平直路段、相同按键持续时间，骑行位移明显高于步行；建议约为步行的 1.5–2 倍。加速、转向、刹停均平滑。
3. 主巷碰撞、建筑、树、栏杆、风险边界仍有效。骑行不把跳跃变成翻栏或过江入口；自动导航也沿可行路网走。
4. 下车仅选陆上可站立落点，人物不落在车架、墙内、台阶悬空处。停下的车与可见车架、碰撞位置一致。
5. 借车不收取物资、不完成“送还手电”等任务，也不自动触发邻近 NPC 对话。没有对话时可重复借还。

### 坐椅读报

1. 坐下后臀部贴近椅面，脚不穿地，身体不穿桌；椅子可见，不以仅改变摄像机高度冒充坐姿。
2. 从第一人称、街巷、全景分别入座、读报、放回、起身；退出后镜头朝向和模式自然恢复，人物留在椅旁合法落点。
3. 读报界面完整显示刊头、虚构标识、期号、三则新闻、小广告与页边暗示。窄屏可滚动，正文不被底部按钮压住。
4. F / 点击只打开一次；Escape / “收好报纸”放回报纸并起身。不吞掉下一次移动、不残留旧的键盘输入、不在后台自动走路。
5. 看报不要求主线进度，不启动 CG，不跳过外公电话，不解锁毛巾回忆。关报、读完、重复读均不写主线数据。
6. 雨后号只在雨后通行消息后出现；回到结局分岔点后恢复雨前号。标题、正文与屏幕天气状态一致。

### 乘船

1. 在岸内候船点主动登船。航行可见船体移动、人物随船移动、沿江视角变化；不是点按钮后只弹“乘坐成功”。
2. 航行中暂停岸上步行、跳跃、自动寻路和附近任务交互；保留看景与明确的回港操作。
3. 航行结束或提前靠岸时，人物到达预先验证过的岸内地面点，恢复站姿与控制。无一次更新把人物暴露在江面行走网格上。
4. 雨中 `checked && !postlude` 时不登船；雨前临时停航与雨后是否复航由统一服务状态决定。按钮、提示与 3D 渡船使用同一状态，不以 `reduced` 或雨粒子可见性判断。
5. “减少动态效果”时，仍可完成登船→靠岸；可缩短或取消颠簸与长距离镜头运动，不让船因为停止装饰动画而永不回港。
6. 正常靠岸、提前靠岸、打开设置、返回主画面、恢复分岔点均清理船上绑定与输入状态。停航期间读报或坐椅不顺带恢复航班。

### 存档与主线隔离

1. 乘船中停留超过自动保存周期，再刷新：落点是本次登船的岸内地面，不是江面，也不是退回游戏初始点。读报/坐下/骑行刷新同样落在合法地面，并恢复默认站姿。
2. 地面持久落点单独保存；临时船上坐标、椅面高度、姿态、镜头、运动插值不当作可恢复的普通步行坐标。
3. 借车→骑行→下车、坐下→读报→放回→起身、登船→回港三组动作前后，对比 `flags`、`supplies`、`lore`、`adventure`、`milestones`、`storyChoices`：逐项相同。允许 `position`、`seconds` 和用户设置正常变化。
4. 完整跑原主线测试，送物次序、应急包、当场报告、结局判定不回归。道具交互的独立 ID 不复用已有 `ferry` lore 点或 `dock` NPC ID。
5. 老存档没有道具字段也可加载；坏的姿态/物件 ID 不产生异常、隐形人物或不可退出的模态框。刷新及离开页面不丢失合法地面落点。

## 4. 接入前架构只读审查

本节记录现有接口的接入风险，不代表上述运行时验收已经通过。实现侧可按函数名定位，避免并行编辑后的行号漂移。

| 位置 | 现有行为 | 接入需处理 |
| --- | --- | --- |
| `main.js` / `save()` | 直接保存 `world.player.position.x/z`，且每约五秒与 `pagehide` 都会保存 | 统一改用返回合法陆地坐标的 `world.getSavePosition()` 一类接口；所有保存入口共用，不只处理按钮退出 |
| `world.js` / `setPosition()` | 仅对 `canWalk` 有效坐标落地；非法值回 `START` | 保存岸上回港点，并在复位前清空道具绑定；避免水上刷新被兜底传回起点 |
| `traversal.js` / `updatePlayerVertical()` | 地面高度来自 `heightAt`，站立状态每帧贴地 | 骑坐/座椅/船体有自己的锚点，隔离竖直运动与跳跃；退出时 `resetPlayerMotion` |
| `world.js` / `endConversation()` | 第一人称分支恢复 `restore.playerPosition` | 读报镜头使用独立恢复快照，或明确处理退出次序，避免起身后又被旧对话快照拉回 |
| `main.js` / `openModal()`、`closeModal()` | 清输入、清路径、结束对话，开关 `blocked` 与 `suspended` | 小报关闭收报并起身；渡船按钮走回港动画，其余关闭路径安全清理，任何路径都可靠复位 |
| `world.js` / `animate()` | 原渡船装饰运动每帧写 `ferry.position` | 航行状态接管船体变换；一个对象不要同时被装饰正弦与乘船控制器写位置 |
| `world.js` / `optimize()`、`bicycle.js` | 普通自行车加入 `world.static`，街道另有固定自行车碰撞体 | 可移动自行车不参与静态几何合批；展示、移动、停放碰撞体由一个所有者维护 |
| `world.js` / 最近交互点循环 | 原列表仅主线 POI 与可选探索，主要比较水平距离 | 道具单独 ID、合理优先级、竖直差与接近门槛；读报和登船不误选邻近 lore/NPC |
| `main.js` / `renderHUD()` | `rainy = checked`，`ended = ending && postlude`；关闭动态只隐藏粒子 | 逻辑天气来自故事状态，不从图像猜测；报纸版次与雨中停航共享同一阶段判断 |
| `endings.js` / `resolveEnding()` | 结局只依赖原故事工作与选择 | 小报暗示纯文本；道具用过与否不加条件、不替玩家决定留下或离开 |

## 5. 自动化范围

`tests/newspaper-data.test.js` 检查两期结构、全局唯一 ID、短文本上限、完整冻结与 JSON 安全、虚构标识、无真实日期/船期冒名、无主线动作字段、无提前揭底。它只验证内容契约，不替代上面的 3D、输入、存档和镜头验收。
