# 《江城有灯》江城顺路小游戏 v1

**这一圈不是为了赢过谁，而是让回家的路，多留下一点故事。**

更新：2026-09-13。本轮先落地两条完整、可重玩的水陆小赛道；自行车、汽车、可控木船与原有旧物谜题共用同一个 3D 世界。两条活动、入口、HUD、剧情日常指南与收藏条件已代码接入；两张纪念图已生成并接入，当前正在进行实机回归。本文是实现与验收约定，闭环以最终回归报告为准。

## 1. 游戏整体的三层循环

| 层 | 玩家做什么 | 带来什么 | 不替代什么 |
|---|---|---|---|
| 主线 | 送还旧物、认识街坊、把安排交到社区 | 剧情推进、互助关系、去留选择 | 不被竞速成绩或刷分代替 |
| 漫游 | 骑车 / 开车、近岸划船、看报、问好、读旧照 | 武汉空间感、日常往事、人物关系 | 不把开过某地等同于读完故事 |
| 顺路小约定 | 水上 / 驾车按标记绕一圈，可暂停、可退出、可再玩 | 个人计时、完成纪念与可收藏画 | 不奖励社区物资、不改变四结局资格 |

玩家可以暂时把委托放一放，去江面上感受划桨；也可以一直跟着主线走。两种节奏都成立。不是把跑腿过程硬性变成关卡倒计时，也不是要求金牌才能听结尾。

## 2. 近岸桨影：一江清风，有来有回

### 入口与人物

从晴川里码头借小木船。**这是玩家自己操控的桨舟，与原有自动渡船并存。** 原渡船仍负责坐船看江的安静片段，不因为新功能被移除。

周伯说：“以前过江赶轮渡，听见汽笛，脚步就快了。今天不赶那一班。”

阿遥问：“那我们比什么？”

周伯说：“比谁把这一小圈划得顺。认青绿浮标，回来我给你留个船票戳。”

对白先给出人物和情绪，再交代玩法。可选邀请不用一大段百科解释武汉轮渡史。

### 自由航行

- 正常走到码头，查看木船说明，再借船。
- 人物落座、穿救生衣，划动时双桨 / 船体有清楚反馈。
- W 划动；S 减速 / 倒划；A / D 转向；F 收桨回码头。
- 松键后逐渐减速，而不是像步行瞬时停住。
- 水域是游戏内近岸练习河湾，浮标和岸线明确边界，不进入现实长江主航道。
- 手账地图在船上切成河湾图，标清码头、当前位置、顺序浮标、回程路线。

### 完整一圈

| 项 | 约定 |
|---|---|
| course id / 模式 | `boat` / `boat` |
| 名称 | 近岸桨影 |
| 起点 | `(42, -38.3)` 附近，容许起点半径 5 |
| 顺序门 | 8 道：向东 → 桥影 → 东侧转弯 → 折返 → 江风回程 → 看见码头 → 收桨 → 返回起点 |
| 计时 | 3 秒准备，随后计时；金章参考 ≤52 秒，银章参考 ≤72 秒，其余有效完赛记完成章 |
| 本轮上限 | 115 秒；超时不记录成绩，提示歇一会儿后从起点重试 |
| 操作 | 顺序通过当前亮起标记；不提前累计后面的门 |
| 结尾 | “桨停下来，桥影又合在了一起。周伯给纪念票盖了个章：不急，江一直在这里。” |
| 纪念 | 一次有效完赛可触发桨影纪念；不要求金章 |

金章只是“划得顺”的一枚纪念，不是赢得周伯认可的门槛。水上赛不引入伤害、险情加分或撞击奖励。

## 3. 江城顺路赛：绕过桥影，回来过早

### 入口与人物

驾驶任意已接入汽车到燕归路起点。正常驾驶仍然自由，只有在明确接受邀请后才开始计时。

蔡姨说：“早先送豆皮，总有人问，顺路能不能捎一份。”

阿遥问：“这一圈，能经过多少户人家？”

蔡姨说：“走燕归路，绕到渡口，再从桥下回来。我们记个时间，不催你，拐弯慢一点。”

这里提到豆皮和捎一份，是生活故事，不凭空添加一份可消耗的社区任务物资。

### 完整一圈

| 项 | 约定 |
|---|---|
| course id / 模式 | `car` / `car` |
| 名称 | 江城顺路赛 |
| 起点 | 燕归路 `(54, 23)`，容许起点半径 5.3 |
| 顺序门 | 8 道：燕归路向东 → 轮渡回车路 → 向江边 → 滨江路向西 → 桥影下向南 → 桥下慢行 → 燕归路转回 → 起点 |
| 计时 | 3 秒准备；金章参考 ≤58 秒，银章参考 ≤78 秒，其余有效完赛记完成章 |
| 本轮上限 | 120 秒 |
| 操作 | W / S 前进、减速 / 倒车；A / D 转向；F 下车即退出本轮 |
| 结尾 | “车停稳了，蔡姨把纸袋递过来：不是奖励。怕你光顾着开车，还没过早。” |
| 纪念 | 一次有效完赛可触发顺路纪念；不要求金章 |

赛道沿宽的公共路线选择，不把穿过居民密集小院或擦撞街坊当捷径。车辆碰撞与转弯手感沿用游戏系统，未完成实机测试前不把参数称作最终竞赛平衡。

## 4. 天气、退出与重试

- 晴日开放；进入 `prepared` / `checked` 的晚间预警阶段且尚未 `postlude` 时，两项活动暂歇。船回到岸上入口，路让给社区安排。
- 雨后能否复开取决于正式剧情条件；`runEnded` 的已结束周目不直接继续刷新成绩。
- 暂停必须同时停计时、停玩家控制，UI 不自行运行时间。
- 失焦 / 隐藏页面自动暂停；回到页面后明确点“继续”，不悄悄计时。
- 打开地图暂停；看完图回去仍处于暂停，由玩家继续。打开剧情等离开活动上下文时可结束本轮，已存的最好成绩保留。
- 退出 / 下车 / 离船 / 超时 / 非法位置跳变不产生完赛结果，不显示成功动画，不解锁纪念。
- 存档只留正常化的完赛次数、最好 / 上次时间、最好奖章；不恢复一半计时、不恢复空中或江心的危险位置。
- 再试一圈要回到起点。小船可从码头重开；汽车需返回燕归路起点，不把“再玩”理解成强行把车和人物瞬移到成绩门里。

## 5. UI 设计和交互契约

### 视觉语言

米白票据、墨绿搪瓷、暖金船票戳；延续现有世界的纸张和黄铜，而不是突兀的霓虹赛车屏幕。手绘 SVG 是玩法说明图，不用 AI 生成伪造实时截图。

| 组件 | 设计 |
|---|---|
| 顺路邀请 | 左侧桥影 / 桨舟或汽车线稿；右侧街坊短句、标记门数、参考时间、操作、两颗明确按钮。 |
| 自由驾驶 / 划船入口 | 右侧中上方小票签，说明是否到起点；不盖住主角或水面前方。 |
| 倒数 | 中央 3 / 2 / 1，只有准备期出现，文字提醒松开按键。 |
| 行驶 HUD | 上方细条：名称、时间、已过门数、下一门、暂停、退出；中央持续留给 3D 操作。 |
| 暂停 | 上方小卡，“歇一会儿，江风也等你”；点击继续，不自动倒数重开。 |
| 成绩 | 个人用时、奖章、门数、最好成绩、街坊短句；再走一圈 / 收好回街巷。 |
| 日常指南 | 两张小约定卡，显示完成次数与最好时间；点击去起点。 |
| 河湾图 | 独立米白航图，绿色水面、虚线路线、金色数字浮标；明确是游戏河湾。 |

### API

文件：[neighborhood-races.js](/Users/baihe/Documents/ChatGPT/腾讯云游戏开发大赛/src/ui/neighborhood-races.js) / [neighborhood-races.css](/Users/baihe/Documents/ChatGPT/腾讯云游戏开发大赛/src/ui/neighborhood-races.css)

- `raceInvitationMarkup(course, availability, progress)`：`data-race-start` / 两处 `data-race-cancel`。只有 `availability.available === true` 可开始。
- `raceResultMarkup(course, result, progress)`：`data-race-retry` / 两处 `data-race-close`。主控制器先记录真实结果，再传进来显示。
- `raceDirectoryMarkup(progress)`：`data-race-route="boat|car"`。
- `mountRaceHUD(root, {onCancel, onPause})`：返回 `update(snapshot, course)` / `dispose()`。`update(null)` 隐藏；`onPause` 传新布尔值。无世界、计时器、存档副作用。
- `raceTimeLabel(seconds)`：固定分 / 秒 / 十分秒，负值和异常值不输出坏时钟。

外层沿用 `paper-panel` 真正的 dialog；内部 ticket 为 group，避免嵌套两个 modal。主控制器负责绑定所有同名按钮、焦点进入可见 close、Escape 与 Tab；HUD 使用 `aria-live="polite"` 只播状态 / 过门，不每帧播时间。

动画只在票据入场和进度短过渡；支持系统 `prefers-reduced-motion` 与 `.reduce-motion`，没有每帧变化的大面积 blur / shadow。

## 6. 与结局、成就画廊相连

两幅新增 Image2 纪念图已经生成、目检并接入画廊：

1. **近岸桨影**：桥影与船桨在江面重合，体现自己划过这一圈的自由。素材：`public/media/gallery-river-oars-v1.webp`。
2. **江城顺路**：停稳的车、过早纸袋和等在街口的人；车是到达的方式，人是画面的中心。素材：`public/media/gallery-road-home-v1.webp`。

生成原图 → 统一画风 / 人物成年形象 → 压缩合适尺寸 → 接入 manifest / 画廊 → 完成事件触发 → 实机点击查看。不能把图片生成成功等同于画廊解锁链已经完成。

基线画廊 **51 位**；本轮已在代码中追加 2 位，共 **53 位**。图片已生成并目检；活动完成到收藏查看的实机解锁链仍在回归。两幅都用有效完赛触发，不用金章门槛；四种故事结局规则保持不变。

## 7. 验收清单

### 可玩闭环

- [ ] 玩家从正常可达码头借船，人物和桨同步；连续前进、转向、减速、倒划、返岸都成立。
- [ ] 不能划上岸、钻过边界、穿进背景渡船；边界反馈清楚，未出现位置或镜头抖动。
- [ ] 两种车都可按正常输入驶到顺路赛起点，不需开发控制台传送。
- [ ] 两条赛道分别真实完整完成 1 圈，8 道门必须按顺序；成绩反映实际时长。
- [ ] 错过门、绕路后回来仍可补过；穿后方门不会跳过下一道门；同一道门不重复累计。
- [ ] 准备期车辆不滑出起点；长按开始键不会同时变成离船 / 下车。
- [ ] 暂停、失焦、地图、退出、F 下车、F 返岸、再玩、回标题、旧存档恢复逐项测试。
- [ ] 晚间预警阶段不新开活动；运行中阶段变化能清楚停止并回归故事。
- [ ] 超时 / 中途取消不显示奖章，不增加完成数，不解锁纪念画；旧最好成绩保留。

### UI / 无障碍

- [ ] 1920×1080 与 1280×720 邀请 / 成绩卡可读；小屏滚动不挡按钮，操作点至少 44px。
- [ ] 进行时不出现中央大剧情卡；主角与下一道门始终留白。
- [ ] 进入票据焦点在可见按钮，Tab 不跑到背后的游戏；两个关闭位置均可用。
- [ ] 键盘读屏可知道当前门、下一处、暂停态；时间不每帧触发播报。
- [ ] 减少动态设置生效；恢复游戏后没有残留 overlay 或世界无法移动的问题。

### 系统与内容

- [ ] 不产生 `supplies` 或主线 `flags`，不改四结局判定；旧自动渡船与所有原谜题回归通过。
- [ ] 正常化结果存储；原始状态、UI 拼接、重复提交不产生新一次完赛。
- [ ] 新纪念画能从一次有效完赛到收藏，再到真实画廊查看，完整打通。
- [ ] 武汉线索具体可见且口径正确；不把艺术压缩桥影当真实桥址。
- [ ] 音效不叠过量、船桨动作与水声节奏一致；失焦不让音效持续高频播放。
- [ ] 录屏只记录通过验收的版本。118 秒参赛片内分别标注可选活动与主线，不让竞速看成救援时限。

## 8. 后续小游戏的筛选准则

以后扩展摆摊配料、旧物检修、船票拼图、街坊投递等，须先回答四个问题：**谁邀请我？我真正操作什么？结束后谁会回应？它为武汉和人物留下什么？**

先把水陆两条做成能反复玩的完整活动，而不是每个角落都加一个薄浅的弹窗。角色、主线、自由漫游和纪念收藏连成同一个生活世界，才是这个“大游戏”的完整感。
