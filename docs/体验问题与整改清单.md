# 《江城有灯》体验问题与整改清单

记录日期：2026-09-08。更新：已开始并完成第一轮功能整合，六项均有对应实现，正式体验标准仍需逐项验收。最新总方案见 [参赛统筹方案](参赛统筹方案.md)，构建和实测证据见 [本轮整体验收记录](本轮整体验收记录.md)。

本清单保留用户首次反馈时的问题依据与验收目标。“当前实现依据”及行号指最初记录时的旧版本。之后已实际改造地图、导航、视角、阴影、美术与动画；不要再把原问题描述当作最新实现，也不要将第一轮实现当作全部质量门槛通过。最终以本轮验收记录和所附构建为准。

最新方向是：**明亮、温暖的动漫武汉小城，以第一人称走进生活；街道有活动、任务有方向、地图真正能用。** 普通对白仍发生在实时 3D 世界，真正的往事才使用 2D 回忆。≥15 分钟的内容容量和武汉辨识度要求继续有效。

## 01 地图简陋、难用，需要精心绘制

**用户原意（整理）**：目前的地图不像一张可以阅读和使用的街区地图，需要认真设计与绘制。

**当前实现依据**：`src/main.js:99` 的 `showMap()` 用固定道路线和 `world.colliders` 的矩形拼出底图；`src/main.js:28` 的 `updateMini()` 使用同类方式。碰撞数据包含建筑与大型家具，它适合判定能否行走，却没有表达街道、院落、门洞和可通行入口的语义。当前已有地点选择与“走到这里”，因此记录的是可读性、路线表达和真实使用体验不足，不是完全没有地图功能。

**具体改造目标**：

- 绘制有武汉街巷气质的插画地图：修理铺、过早铺、婆婆院落、公共小屋、码头有各自的轮廓和小图标；江岸、老巷、门洞与院落形成清楚的空间层次。
- 美术底图与世界坐标统一标定，导航路径和地点数据单独叠加；底图不再直接把每个碰撞箱画成建筑。
- 清楚区分可走公共通道、建筑、不可达区域、风险观察点与已关闭通道。标出院门、台阶、坡道、连通口；地图画出的路必须真能走。
- 同时表达玩家位置和朝向、当前任务地点、已探索位置与选中的路线。主任务突出显示，支线不过度抢占视线。
- 支持拖动、适度缩放、回到玩家位置；手机上避免手指挡住说明，地点选择与“开始导航”分开，保留键盘操作。

**视觉与交互验收目标（待实测）**：

- 在 390 × 844 手机与 1440 × 900 桌面检查：地图无横向页面溢出，主要地点名称不互相遮挡，触摸热点至少 44 × 44 CSS 像素。
- 绘制出的全部主线入口与 3D 实际入口一一对应；从修理铺到婆婆、过早铺、码头、社区的路线逐条实走通过。
- 三名首次试玩者均能在 10 秒内指出“我在哪、朝哪边、下一站在哪”，无需解释图例；记录具体误读位置。
- 选择目标后能明确看到路线、预计行走距离和抵达位置；不可达时说明原因，不出现虚假的成功导航。

实施优先级：高。与第 06 项共用同一份可行走路线数据，先校准空间，再精绘底图。

## 02 小城缺少动态生活，人物要真正活动

**用户原意（整理）**：小城需要动起来，有烟火气；人不应像静态摆件。

**当前实现依据**：`src/world.js:103` 已创建蒸汽粒子；`src/world.js:126` 创建五名路人；`src/world.js:262` 已有江水、轮渡、蒸汽与路人往返。当前路人主要按正弦函数平移，常驻居民主要是轻微整体摆动；与摊铺、工具、邻里关系对应的连续动作和生活安排仍不足。`src/world.js:264` 按天气统一控制居民显隐，还没有可见的避雨过程。

**具体改造目标**：

- 给四个核心地点建立各自的生活节奏：修理铺整理工具，过早铺拌面或擦桌，婆婆看收音机与照料盆栽，码头附近的居民慢走、停留和望江。
- 每个角色用明确的“行走—停下—做事—交谈”状态控制；行走有腿部步态和自然转向，手与工具、碗和桌面的接触保持稳定。
- 让蒸汽、树叶、晾晒物、江水、船只与近处环境声共同形成生活感，避免所有对象以同一频率摆动。
- 路人沿真实可走通道活动，停靠点避开门口和任务点；玩家靠近时能礼让，交谈时停止无关动作并看向玩家。
- 天气变化时表现为收拾摊面、走到安全室内、窗边灯光与屋内生活声接续；不把危险天气表现成热闹的涉水活动。
- 远处角色采用简化动画，屏外暂停高成本动作；“减少动态”设置仍能提供稳定可读的人物和任务信息。

**视觉与交互验收目标（待实测）**：

- 在修理铺、过早铺、院落、码头各观察 60 秒，至少看到一种地点特有动作和一种环境变化；不同地点的生活节奏有区别。
- 连续录制五分钟路线：无路人穿墙、脚底长距离滑动、工具悬空、人物重复碰撞任务入口；明显转向不突然掉头。
- 与四名居民分别开始和结束对话，动作能平顺停下与恢复，任务状态不受动画影响。
- 雨前到雨中能理解居民去了哪里，雨后恢复生活有依据；加入动态后须重新通过第 03 项性能门槛。

实施优先级：中高。先做四名居民的少量可信动作，再扩展路人数量，数量不作为完成标准。

## 03 阴影持续刷新与卡顿，需要性能定位和改造

**用户原意（整理）**：阴影一直刷新，体验卡顿，需要解决。

**当前实现依据**：`src/world.js:22` 设置 `renderer.shadowMap.autoUpdate = false`；`src/world.js:24` 配置 4096 × 4096 的太阳阴影；但 `src/world.js:268` 在每次实际渲染前又设置 `shadowMap.needsUpdate = shadowMap.enabled`。因此在精致模式中，当前代码会为每个实际渲染帧请求阴影更新。**这是已确认的持续开销模式；尚未完成针对用户设备的 profiling，不能把它断言为卡顿的唯一根因。** 水面反射、SSAO、透明效果、像素比、CPU 逻辑和资源加载也需要分别测量。

**具体改造目标**：

- 用同一设备、同一画质、同一路线建立基线，记录平均帧率、帧时间 P95、长帧、绘制调用与各渲染过程的成本，区分 CPU 与 GPU 开销。
- 拆分静态建筑阴影与动态人物阴影的需求。静态部分优先烘焙或缓存；动态人物保留必要的接触感，以较小覆盖区和适当分辨率更新。
- 仅在影响静态阴影的光源、场景或配置确实变化时使其失效；不能简单永久冻结整张阴影，导致走动人物留下旧影。
- 实测 4096、2048、1024 的效果与成本，按画质档位选取；调节阴影视锥、稳定采样与偏移，控制树叶和细小道具的投影成本。
- 同步检查反射与后处理，保留必要的空间层次；流畅模式具有完整可玩的视觉反馈，不能靠丢失角色、目标或道路换帧率。

**性能与视觉验收目标（待实测）**：

- 固定场景、光源和投影物不变时，静态阴影更新计数不随每帧无条件增长；角色移动时没有残留影子、突然跳影或明显悬浮。
- 在记录设备型号、系统、浏览器、分辨率、画质档位后，各跑静止 60 秒、街区步行 120 秒、雨中移动 60 秒，保存修改前后的同条件数据。
- 目标门槛：基准桌面精致模式持续行走平均 ≥60 FPS、帧时间 P95 ≤20 ms；选定手机真机的流畅模式平均 ≥30 FPS、P95 ≤40 ms。设备名单需先确定，这些数字是待验证目标，不是当前实测结果。
- 预热后连续五分钟主线行走，不出现可重复的 >100 ms 卡顿；若出现，保留时间点和 trace，定位后复验。
- 近景人物、细密树影、相机移动和雨后灯光逐项检查；禁止以阴影闪烁、严重锯齿或丢失人物接地感换取指标。

实施优先级：最高。先定位和建立预算，再增加生活动画与新特效。

## 04 行走需要第一人称

**用户原意（整理）**：以第一人称在街区中行走，真正置身于这座小城。

**当前实现依据**：`src/world.js:170–171` 的 `start()` / `setView()` 使用 `streetView` 二态，分别给出第三人称街景和全景俯瞰位置；`src/main.js:106` 的按钮在这两种状态间切换。当前没有独立的第一人称相机模式，街景镜头靠近角色不等于人眼视角。

**具体改造目标**：

- 增加真实的第一人称行走，默认眼高随地面、坡道与台阶平顺变化；相机位置位于角色内部合理的人眼高度，不沿用绕角色旋转的 OrbitControls 偏移。
- 桌面使用 WASD 和鼠标观察，进入鼠标锁定须由明确点击触发，Esc 可退出；提供灵敏度设置。手机提供独立移动与观察区域，支持同时操作。
- 碰撞与相机共同遵守建筑、桌面和风险边界；视角不能钻进墙里，也不能看见自己的头部内侧。
- 默认关闭强烈摇头、奔跑抖动和突然滚转；如有步行起伏，应细微且可关闭，限制仰俯范围但不强制夺走玩家朝向。
- 第一人称交谈仍留在 3D：看向面前居民，显示克制的对白界面；进入与退出不跳到地图另一侧。打开菜单、观看回忆再返回时恢复原位置和朝向。
- 原有全景作为可选观察方式保留，清楚标注模式；切换不改变任务状态、人物位置或已选择目标。

**视觉与交互验收目标（待实测）**：

- 用第一人称完整完成主线和所有必要互动，不依赖第三人称才能发现或点击的物件。
- 逐一经过窄巷、门口、雨棚、台阶、院落和摊位；无穿墙、看入模型内部、视角剧烈抬升或转向失控。
- 对话、菜单、2D 回忆、视频分别进入退出五次，位置与朝向恢复正确；鼠标锁定不困住用户，Esc 行为一致。
- 三名首次测试者各行走十分钟，记录眩晕、方向误判和操作中断；明显不适需要调整相机参数后再测。

实施优先级：高。先确定人眼视角，再检查近距离建模、道路指引与美术构图。

## 05 整体改为明亮动漫风，减少压抑暗沉

**用户原意（整理）**：整体要明亮、温暖、动漫感更强，不要一直昏暗压抑。

**当前实现依据**：`src/world.js:21–25` 的背景、灯光、曝光和后处理，以及 `src/atmosphere.js:9–15` 的天空渐变、`:43–45` 的环境强度和雾色，共同形成当前偏灰绿、米褐的傍晚基调。HUD 在 `src/main.js:25` 将早期场景表述为“日落时分”。当前外观还由建筑贴图、植被、人物配色与 UI 共同决定，不能只改一个曝光值就视为完成。

**具体改造目标**：

- 先确定新版风格板：清透天空、明亮的青砖与浅墙、温暖的木色、鲜活但不过饱和的植被；人物有可读的面部与干净色块，保留细节和被使用过的生活痕迹。
- 用更清楚的形体、柔和的明暗层次和受控的材质高光形成动漫感；统一建筑、人物、道具、地面、天空、雾与 UI。
- 武汉识别依靠江岸、轮渡、江汉关、长江大桥形态、汉口老街与过早生活；风格明亮化不削弱地标方向和街区空间关系。
- 为晴朗日间、雨前、雨中、雨后与回忆制定独立配色；夜雨保留前中远景与人物可见度，以冷暖和灯光叙事，不能全屏压暗，也不能只把曝光拉高造成泛白。
- 首先制作修理铺、过早铺和江岸三个代表视角的新版目标图，再用实机第一人称和全景对照，逐项调整而非仅改宣传图。
- C01、C04、C09 三条 Seedance 样片按此前风格制作，作为旧版风格样片保留；后续首尾帧、短片调色或重生成需服从新版统一规范，不能把既有样片宣称为新版动漫风已验收成片。

**视觉验收目标（待实测）**：

- 五种天气／叙事状态均提交同机位前后对照；人物脸、入口、台阶、目标物和可走路面在阴影中仍清楚，窗灯和天空不过曝成无细节色块。
- 三个代表地点分别检查第一人称、对话、全景；近处纹理、模型尺度与远处地标保持一致，不出现“宣传图明亮、游戏仍旧灰暗”。
- 三名首次测试者对“明亮、温暖、有生气”的五级评价中位数至少 4 分，记录不达标画面并返修；武汉辨识度按既有盲测要求另行验证。
- 游戏、地图、2D 回忆、视频和 UI 进行并排审核，列出仍沿用旧版色调的资产；未统一的资产不得笼统标为美术改版完成。

实施优先级：高。先立规范并做三个样板，再覆盖全城与影片；以当前用户方向为准。

## 06 任务方向与导航必须清晰

**用户原意（整理）**：玩家应当明确知道接下来去哪、怎么走，不靠猜方向。

**当前实现依据**：`src/main.js:25–27` 已显示当前任务文字与地点标签；`src/main.js:106` 的任务按钮打开地图。`src/world.js:159–169` 已实现四邻域寻路与目标附近停靠，可沿碰撞边界绕行。但是现有地图没有绘制这条路径，HUD 的世界地点标签主要是目标投影；尚无持续的、相对玩家方位的下一转弯指引。应复用和完善可走路径，不另做一支永远直指目标的箭头。

**具体改造目标**：

- 固定显示一个明确的当前任务目标，提供“开始引路／取消引路”。抵达与完成后及时更新，不让已完成目标继续发光。
- 方向以玩家当前朝向和**下一段可行走路径**为准：提示“前行至巷口”“右转进入院门”等；距离使用沿路径的距离，避免隔着楼显示误导性的直线捷径。
- 地图、迷你地图与 3D 引导共享路径和目标入口；3D 可用少量地面光点或克制箭头突出下一拐角，不能画穿墙、穿楼、穿家具的直线。
- 一般探索仅保留轻量目标方向；需要时展开引导。关键路口加强提示，抵达对话范围后切为“与蔡姨交谈”等具体动作。
- 玩家偏离路线后平稳重新计算，堵路或目标转移时更新；不存在可达路径时解释原因，提供返回最近公共通道的合理引导。
- 自动行走与手动引路分清：手动输入立即中断自动移动，但可保留任务指引；第一人称抬头、转身、开地图后方向仍一致。

**视觉与交互验收目标（待实测）**：

- 验证全部主线段、物资搜寻和返家；每段从两个方向开始，路线都避开建筑、家具与风险区，进入真实入口并停在可交互位置。
- 在“目标就在墙后”“玩家背向目标”“连续两个转角”“临时偏离路线”“雨中居民已入室”五类场景中，提示与实际路径一致；不指向隐藏人物或不可达区域。
- 三名首次玩家能仅凭游戏提示完成主线；任何超过 30 秒且需要外部解释的迷路均记录为待修问题，不能靠测试者熟悉地图判通过。
- 手机与第一人称中指引不遮挡人物面部、对白选项和路面危险；玩家可以取消引导，探索权不被夺走。

实施优先级：高。与第 01 项同步，第一人称完成后必须重新检查方向语义。
