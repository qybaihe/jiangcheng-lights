# 世界交互与渲染接口

本轮由 `src/world.js` 负责眼位相机、走路与路径、对话镜头、阴影缓存和物资状态反馈。界面仍由 `main.js` 负责；人物动作由 `town-life.js` 负责。

## 视角与输入

- `setCameraMode('first' | 'street' | 'overview')`：切换并返回模式。`start()` 保留已选模式；旧的 `setView(boolean)` 继续兼容街巷／全景。
- `cycleView()`：人眼 → 街巷 → 全景。
- `getHeading()`：弧度，`0` 朝世界 `-Z`（地图上方），`π/2` 朝 `+X`（地图右方）。
- `setLookDelta(dx, dy)`：像素位移；第一人称用独立 yaw/pitch，固定眼高为脚下地形上方 1.65 米。视角直接设在玩家眼位，完全不执行 OrbitControls 更新；没有强制头部晃动。
- `requestPointerLock()`／`releasePointerLock()`：鼠标锁定须由用户手势触发；Esc 主动退出。未锁定时支持鼠标或触屏拖动观察。

第一人称隐藏主角全身。普通交谈暂时显示双方并使用原有实时 3D 双人镜头；退出后直接恢复交谈前的世界位置、yaw、pitch、眼高与视野角，不通过第三人称轨道退回。

WASD／方向键相对当前朝向移动。移动与路径都检查建筑、家具、灯柱、水边边界、风险区域和台阶高度；NPC 周围保留约 0.52 米的身体间距。路径规划避让可见街坊；若路人走到路线中途，会重新绕行，不把路人的当前位置写入永久障碍地图。

## 可走路径与引路

`getNavigation(targetIdOrPoint, { approach: true })` 返回：

```js
{
  reachable: true,
  path: [{ x, z }], // 从真实当前位置开始，包含实际停靠点
  distance: 24.6,  // 沿路线的世界单位长度，不能拿直线距离替代
  target: { x, z },
  targetId: 'granny',
  reason: null
}
```

查询不移动玩家。`navigateRoute(route)` 执行已计算路线；`navigate(x,z)` 用于原有双击行走；`approach(point)` 在人物或物件旁停下。不可达返回空路径与原因，不能画穿墙的直线代替。

路径用同一套脚底碰撞和台阶检测接入 A*，再逐段检测后简化。会从楼梯进入婆婆的小院，不从台基侧边直接爬上去。自动行走优先执行整段向量步长，遇阻才沿障碍滑动，避免逐轴移动把原本可走的斜线挤进墙角。

`setGuidance(routeOrPathOrNull)` 最多显示前方 15 米、12 个克制光点，重新检查每一段可走性，按实际地形放置。主界面可按较低频率重新查询路线，不需要每帧运行 A*。

## 对话取景

保持原有双人构图接口 `beginConversation`、`setConversationSpeaker`、`endConversation`。候选视点检查双方眼部与脚部到镜头的射线，并要求相机离场景包围盒至少 0.45 米。街灯灯头、灯柱、树冠、屋体、雨棚与招牌参与遮挡检查。最终验收仍须看实际截图；人物投影在屏幕内不能证明没有前景遮挡。

## 静态阴影与动态物体

4096 阴影贴图按需更新，移除原先每个渲染帧强制刷新的逻辑。城市静态几何与树叶实例写入静态阴影；人物、渡船、可领取物资与送餐箱不写入缓存，防止移动或隐藏后留下旧投影。人物脚下的柔和接触阴影实时跟随位置，少量微风叶片使用静态树冠投影。

- `requestShadowUpdate(reason)`：几何、太阳方位或投影形状真正变化时显式失效。
- 追踪 alpha 贴图的版本；异步加载或更新改变剪影时只补一次更新。当前叶片来自同步 CanvasTexture，不必为了颜色贴图下载完成重绘整张阴影。
- `getShadowStats()`：返回实际阴影绘制更新次数、已渲染帧数、请求次数、最近原因、脏状态、alpha 贴图数量等。通过静态投影网格的 `onBeforeShadow` 回调计数，避免把普通帧数误当阴影更新数。
- 流畅画质关闭阴影贴图、AO、Bloom；切回精致画质补一次阴影。减少动态暂停居民移动与场景微动，但观察和行走仍可用。

### 地面斜条修复

宽斜条与黑色三角块来自两层不同材质的铺地顶面共面：218 × 149 的底层与 79 × 59 的游玩区顶面原来都在 Y = 0.07。固定机位关闭阴影和 AO 后问题仍在，仅隐藏底层便消失，因此修复几何重叠，没有调整阴影偏移来掩盖问题。

底层顶面降至 Y = -0.01；横街拆为两侧铺地，与中央 9 米宽主街沿边相接。地面只接收阴影、不投影，静态批处理按材质和投射／接收阴影意图共同分组，避免合并后覆盖原有标志。树木与建筑的正常投影保留。相同机位的前后图与诊断图位于 `output/qa/world-ground-*.png`，修后报告 `output/qa/world-ground-after.json` 确认 91 个实际渲染帧内没有额外阴影更新。

## 物资与互助的场景反馈

原位置的保温箱、瓶装水和备用电池属于独立场景组，`collectedSupplies` 决定是否还在货架上。收走电池不会移除雨棚。`storyFlags` 含 `chef` 后，蔡姨摊边出现打包好的街坊热食箱；含 `checked` 后，箱子显示在社区门前的干燥位置。可变物件不写入静态阴影缓存。

## 验证入口

```bash
node --test tests/world-navigation.test.js
node tests/world-runtime.mjs
node tests/world-performance.mjs
node tests/world-ground.mjs
```

第一项测试浮点路径、薄障碍、台阶、居民绕行与第一人称恢复。第二项在独立浏览器世界验证真实输入、物资变化、阴影缓存、实际走到目的地后的镜头；不会改用户存档。第三项测量真实 `main.js`、生活动画、引路和地图 HUD 一起运行时的 FPS 与帧间隔 P95，并记录源文件哈希。性能采样时只开一个活动 WebGL 画面。

结果位于 `output/qa/world-runtime-report.json` 与 `output/qa/world-performance.json`。技术断言与实际截图审查分别保留；历史失败截图不删除。

### 2026-09-08 专项结果

路径／眼位／阴影批处理单测 **8 / 8**。地面修复前的完整独立浏览器专项 **16 / 16**，归档为 `output/qa/world-runtime-report-2026-09-08T12-34-33-770Z.json`；其中真实走完婆婆 → 蔡姨、电池 → 蔡姨后再开始交谈，已逐图检查灯体遮挡消失。地面修复后补跑渲染与输入回归 **14 / 14**，归档为 `output/qa/world-runtime-report-2026-09-08T12-48-02-930Z.json`，明确省略了两条实际行走路线，保留所有目的地路径合法性、缓存／alpha 失效、真实输入、身体碰撞、眼位恢复和物资反馈检查。测试用截图是无正式对白 UI 的独立世界取景，主界面仍需由完整游戏通关验收。

阴影测试先确认连续 45 个以上实际渲染帧没有新增更新，再主动修改 alpha 贴图版本、切换流畅 → 精致画质；约 3300 个渲染帧内累计只有初始、贴图失效、恢复画质这 **3 次**投影更新。后两次由测试明确触发，不代表正常运行会周期刷新。

短时性能条件：Apple M3 Pro，Chrome 149 headless，1440 × 900，设备像素比 1；单个游戏页，真实主界面、生活动画和引路 HUD 开启。每项预热后采样约 4 秒，第一人称样本包含向前行走，另两种视角为生活动画仍运行的固定取景。
