# 《江城有灯》第三稿：独立冷读初审

审读范围：`src/story.js`、`src/dialogue-presentation.js`、`src/ui/memory-game.js`、`src/main.js` 的影片入口与结尾、现有剧情链路及短片导演案。本文只审稿，不修改游戏、不生成媒体。

## 总判断

现稿的好材料已经很多：少葱到吃葱、红盖饭盒的白点、外公不会煎豆皮、杯盖一直没打开、旧书包的补丁，都比抽象的“温暖”有力。问题不是事情太少，而是每件小事旁边又补了一层解释，几个人接连替主题作结，玩家还没来得及想，旁白就先感动了。

下一稿宜做减法：**让阿遥带着一个明确的小目的回来，做着事认识人，最后自然多住一晚。** 不给阿遥追加失业、失恋、重病等未经铺垫的重大创伤，不把外公改成逝者；不靠对白和长视频凑十五分钟。

## 八个最影响代入的问题

### 1. “回来办什么”没有说清，“外公还在不在”反而反复解释

现稿说“离开武汉七年”，却只给“我把东西送到，明天把店收拾一下，就……”这一句含混动机。门、旧字条、旧布、半句话和“我以为早就……”都借用了悼念戏的语法，随后再用姨妈照片解释外公健在。玩家先猜死亡，再被纠正，注意力被错误悬念占用。

**建议：** 开场一通简短活人电话，第一回合交代“外公在姨妈家休养；阿遥回来替他收拾铺子、送三件修好的东西；原计划待一天”。不解释七年每一天去了哪儿。挂断电话，阿遥提一下门再推开，老门的笑点保留；把完整动机放在动作前，不再靠省略号藏信息。

### 2. 序章给玩家十五段文字，还没动手就要求怀旧

现稿连续展示身高线、蓝布、橘子照片、钟声、鞋带、钥匙。它们都想提前成为情绪物件，但玩家还没认识这家人。句子如“三件旧东西，像三个等着被叫到名字的人”，在读物里成立，在可玩的开场里使“拿起收音机”的时间越来越晚。

**建议：** 必经序章只保留门、电话、三件委托、收音机没响四件事。身高线和蓝布改为可点看的环境信息，蓝布到结尾再承接。首次取得控制前只回答：这是武汉、我为什么回来、谁在等东西、下一步按哪里。新序章应按演出动作测时，不按文字页数扩写。

### 3. 阿遥常替作者发问，而不是作为街坊的小辈说话

“您是说，现在大家不缺修理的东西了？”“他难的时候，您怎么知道该问？”“原来这条巷子，也接住过刚来的您。”三句都像访谈提纲，功能是把居民引到主题宣言。阿遥在不同人面前的关系相近，声音不够具体。

**建议：** 用能立即回应对方眼前行为的话替代抽象追问，例如看到旧饭盒直接问“红盖子的那个？我还带去过学校。”婆婆可以认出脚步或习惯，但阿遥只需回一句“我都这么大了，您还记这个。”主角的发现落在物件辨认和突然接上的记忆，不落在概念提炼。

### 4. 四位街坊说的是同一个道理，结尾又完整复述一次

婆婆：“他什么都不修，来我这里坐着，也算来客。”蔡姨：“不是回来帮了多少忙才高兴。”周伯：“人不跟东西一样，不能替别人决定怎么修。”小许：“明天没委托，也可以来坐。”外公再说“不是要你回来还谁的情”。这些句子各自都温柔，连在一起会显得所有人事先商量好给阿遥上课。

**建议：** 每人只贡献一条不同事实：婆婆曾照看孩子；蔡姨曾留下两份饭；周伯陪外公把工具搬回去；小许让今天的帮助真正交接完成。只有结尾允许一句总意思，而且优先让阿遥说出自己的发现。其余人的温柔用添筷子、检查电池、把纸压住等事情表达。

### 5. 四张照片排序，是“操作界面先有、剧情后找理由”

现稿要求排“没开门→端碗→坐下谈话→留下位置”，像有人替一次私人照顾拍了连续四机位；婆婆还说“眼睛不比从前，别拿顺序考我”，紧跟阿遥“您记得我没写作业，倒把照片顺序忘了”。这把老人先塑造成记不清，再让玩家做阅读理解。背文直接写“敲门后”“坐下之后”“听完后”，也没有发现的乐趣。

**建议：** 保留四卡排序及现有完成旗标，但把物件解释为**阿遥小时候画的四格画页，散在旧相册中**。婆婆要的是装回相册，不是让玩家考试；她记得当年，是阿遥在认自己的画。排序依据可以是同一碗从满到空、书包从背上到竹床边等具体连续性。现有四张 SVG 本来就近似画页，改呈现文案即可有更合理基础；正式实施另核对图像，不用本轮生成资源。

### 6. 周伯故意不给答案，会让互助故事像外公安排的“情感闯关”

阿遥问“后来呢？”，周伯答“后面的事，在这只信封里……先把今天的安排办妥……再慢慢看”；接着说明外公要“让你见见活生生的人”。纸上可以管住剧透，但角色的行为像关卡管理员：明明一句话能答，却要玩家先做任务才兑奖。

**建议：** 周伯直接答“搬回去了”，只不讲重开那晚的全景。他顺手交出清理旧抽屉找到的照片，请阿遥带回铺里；此刻小许的联络电话或雨前收摊自然打断谈话。阿遥自己把纸袋收好、去办眼前事，不由周伯禁止看。终局不是被扣住的“答案”，而是几件已经听过的小事，在照片里第一次出现在同一个晚上。

### 7. 应急知识进入了每个人的口癖，重复确认挤占人物节奏

蔡姨把“密封、规格、实际需要、饮食限制、确认领取、交付、干燥公共通道”集中说出，阿遥完整复述；小许再区分“人、物、到达”，prepared 又复述“准备好不等于都到了”，checked 再作总结。必要的任务闭环是清楚了，听感却像每人都拿着验收表。

**建议：** 保留真实操作约束，**将具体物资与安全边界主要写进任务卡、地图和小游戏说明**。口头只交代一件当下最重要的事，例如蔡姨“帮我拿回来，我得看一眼”；小许在风险任务开始时给一次明确指令，回报时确认结果。不删不涉水、不触碰电气设备等关键限制，也不把观察升级成主角冒险处置。对白体现人正在忙什么，不背完整制度。

### 8. “十秒 CG”与主线是两套东西；单纯加长镜头不会让故事更完整

代码 `playFilm('arrival')` 播放 `/media/arrival.mp4`，是现有约十秒的开场城市镜头，字幕“七年以后，我又回到了武汉”。尾声也单独播放约十秒江城镜头。八张 `story-v2-cg-*` 则由逐句对话推进，并不是八条各十秒视频。旧导演案虽有十镜七十八秒的总规划，但它不等于游戏现已播放一段连续的故事短片。

**建议：** 新序章按“到武汉→接外公电话→到铺门口→自己开门”建立一段小事件。可先纸面编为约三十五至五十秒、三四镜，不把任何一镜强拉到十五秒。开场城市镜头承担定位，电话承担动机，门承担个性，最后的动作接玩家控制。回忆 CG 每次只演一个新增事实；先玩再触发，不把对白原句再拍一遍。镜头和时长在新稿验收后才进入资源调度。

叙事重心逐步变化：**送完就走 → 原来这事跟我有关 → 今天这件事我也在场 → 明早再吃一碗。** 外公当年的具体困境只需一个稳定事实链：铺子漏水受潮、几天没开、带孩子与修理顾不过来。不要再叠一场未说明的生死事故。

## 武汉特色的冷读标准

1. 地名不是贴纸：到城镜头负责江与武汉轮渡/钟楼识别，口语不要轮流报地标。
2. 过早要在手上：酱黏了要拌、葱另放、豆皮蛋皮被挤破，比介绍“武汉人把早餐叫过早”更有生活。
3. 方言只留角色自然会用的“么急、蛮好、莫”，不句句标注口音；年轻阿遥与年长街坊有差别。
4. 竹床、天井、连廊、门槛、锅盖是事件发生的条件，不是景物名词列表。
5. 只写已核实的地标与生活要素，不临时捏造某年真实防汛事件来放大感情。

## 下一轮逐场验收表

- 一场对话里，每句话是否在回答上一句或处理眼前动作？跳出来单独当金句的句子优先删。
- 一口气是否说得完？超过两个转折、三个任务事实的台词拆分或转交 UI，不机械按字数切页。
- 遮住说话人后，是否仍能分出蔡姨的利落、婆婆的熟稔、周伯的少话、小许的忙中仔细？
- 本场是否真的新增了一条信息？只重复“你不必有用才被喜欢”的场次判为重复。
- 旁白是否只写可见可听的动作？“原来、忽然懂得、终于明白、才让它那么普通”类解释只择极少数保留。
- 玩家是否知道下一步，却没有听到第二份任务说明书？
- 若完全关掉音乐与配音，情绪是否仍能靠具体事件成立？
- 哭点是否来自“我认出了与自己有关的东西”，而非“角色告诉我这很感人”？
- 外公健在、两盏灯去向、旧照片来源、当年时间关系、当下天气与安全回程，是否一遍就读懂？
- 新稿只评自然度、因果与节奏。十五分钟有效玩法另做首次试玩，不把读稿时长当成玩法容量。
